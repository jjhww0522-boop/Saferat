# 03. 회원·사고·운영자 화면 명세

작성일: 2026-09-14. 아래 버튼·문구·색상은 디자인 제안이다. 공사 로고나 공사 공식 서비스라는 표현을 사용하지 않는다.

## 1. 화면 원칙

- 모바일에서 오늘 해야 할 일과 다음 행동이 먼저 보인다. 전문 법률 설명은 근거 펼치기로 제공한다.
- 앱은 한국어로 구현한다. 카드에 ‘해야 할 일 / 이유 / 기한 / 준비물 / 다음 행동’을 일관되게 배치한다.
- 긴 양식은 단계별로 나누고 임시 저장·뒤로 가기·직접 입력·모름을 지원한다. 같은 확정 정보를 문서마다 다시 묻지 않는다.
- 중요한 버튼은 충분히 크게 하고 키보드 탐색·화면낭독 레이블·오류 연결을 지원한다. 색만으로 상태를 구별하지 않는다.
- 기본 배경은 밝은 중립색, 주요 동작은 파랑, 보완은 주황, 긴급은 빨강을 제안한다. 화면별 제목·버튼·표의 간격을 통일한다.
- 로딩·빈 목록·권한 없음·네트워크 실패·부분 저장·재시도 상태를 구현한다. 단순 성공 토스트로 서버 오류를 숨기지 않는다.
- 정보 입력/증빙 확인 진행률을 법적 안전도나 사고 발생 확률로 표현하지 않는다.

## 3. 가입과 사업장 등록

### 3.1 계정·조직

첫 화면은 ‘새 사업장 시작’과 ‘초대받은 사업장 참여’를 구분한다. 사업자번호가 같다는 이유로 기존 고객 데이터에 연결하지 않는다. 중복 등록 시에도 기존 고객의 이름·가입 여부·담당자를 노출하지 않는 확인 절차를 둔다.

### 3.2 등록증 업로드

선택지: 사진 촬영 / PDF·이미지 선택 / 직접 입력. 사업자등록증이 없는 기관 등도 수동 등록 경로가 있어야 한다.

추출 후보는 상호, 사업자번호, 대표자, 소재지, 복수 업태·종목, 개업일 등 문서에 실제 있는 정보다. 원문 영역과 후보 값을 나란히 보여주고 사용자가 확인한다. 개업일과 발급일, 본점과 현장 주소를 구별한다. 불필요한 주민등록번호·생년월일은 기본 입력 항목으로 수집하지 않는다.

OCR 진행 실패 시 ‘다시 촬영’과 ‘직접 입력’이 가능하다. 신뢰도는 문자 인식 참고 정보이며 법적 정확도 백분율로 보여주지 않는다. 국세청 대조가 붙어도 가입자의 소속·대표 권한 확인과 별도 상태다.

### 3.3 최소 질문과 후속 질문

첫 입력은 실제 하는 일, 관리할 현장 주소, 인원과 기준일, 본인의 역할 정도로 시작한다. 해당 의무에 필요한 설비·물질·건물·공사·도급 질문은 선택한 활동에 따라 이어진다. 처음부터 모든 업종 질문을 노출하지 않는다.

‘현재 인원 N명’ 다음에는 법령 산정에 필요한 범위에서 고용관계·기간을 확인한다. 모르는 경우 ‘나중에 확인’을 선택할 수 있지만 이를 의무 없음으로 계산하지 않는다. 추가 질문 카드에는 왜 필요한지 한 문장으로 설명한다.

### 3.4 결과

상단에 ‘정보 확인 완료 / 추가 질문 / 적용 의무 / 적용 범위 검토 중’을 분리 표시한다. 첫 행동은 가장 중요한 자료·정보 보완을 제안한다. ‘모든 법령 분석 완료’ 같은 문구를 사용하지 않는다.

## 4. 홈과 의무 상세

홈에는 기한 임박·새 보완 요청·확인해야 할 사업장 정보·다음 교육/점검·이번 검토 상태를 보여준다. 적용 의무가 아직 없으면 등록과 추가 확인을 안내하며 완료 화면을 띄우지 않는다.

의무 상세 필수 요소:

1. 해야 할 일과 대상·책임 주체.
2. 왜 적용되는지: 확인된 사실, 법적 근거, 적용 시점.
3. 기한·반복 주기와 계산 근거, 담당자.
4. 필요한 문서·실제 행동·사진·서명·외부 수행/제출 조건.
5. ‘초안 만들기 / 기존 자료 올리기 / 수행 내용 기록 / 검토 요청’ 중 현재 가능한 행동.
6. AI 의견·사람 검토·제출·이력의 상태와 다음 단계.

‘해당 없음’은 사용자가 클릭해 지우는 버튼으로 만들지 않는다. ‘적용 정보 수정 요청’을 통해 관련 사실·근거를 남기고 재평가한다. 운영자 판단 변경도 근거·이력 없이 덮어쓰지 않는다.

## 5. 문서 자동 작성과 사진 점검대장

| 흐름 | 사용자 경험 | 데이터 조건 |
|---|---|---|
| 계획 초안 | 기존 현장정보 자동 채움 → 실제 목표·담당자·일정·예산 등 필요한 결정만 입력 → 미리보기 → 확인·출력 | 적용 의무/서식 버전과 입력 출처 연결 |
| 사진 점검 | 촬영 가이드 → 사진·관찰 후보 → 사용자가 위치·대상·실제 확인 결과 입력 → 개선 과제 → 대장 출력 | 원본과 주석본 분리, 미확인 값 허용 |
| 교육 기록 | 대상·내용·일정 → 실제 실시·참여·자료 확인 → 기록 연결 | 파일 생성만으로 이수 완료 불가 |
| 선임 기록 | 대상 직무·자격 확인 → 실제 선임일·증빙 → 보고 필요 시 제출 관리 | 앱 권한과 법적 선임 분리 |

계획에 없는 예산·사람·활동을 AI가 채워 넣지 않는다. 입력이 없으면 ‘결정 필요’로 표시한다. 사진으로 확인할 수 없는 설비 작동·전압·가스농도·체결력 등을 측정값으로 생성하지 않는다.

출력 문서에는 자체/법정 서식 구분, 초안/확인 상태, 작성·확인 시점, 적용 서식 버전, 필요한 미확인 항목을 표시한다. 공식 서식은 해당 파일 형식·필수 필드·버전을 확인한 것만 법정 서식으로 제공한다. 일반 HTML을 PDF로 출력한 것만으로 기관 수리 가능을 보장하지 않는다.

## 6. 보완·상담과 정기 검토

검토 요청은 제출 문서 버전에 고정된다. 보완 요청에는 부족한 항목, 원본 위치, 근거 또는 권고 구분, 필요한 행동·자료, 담당자·기한이 있어야 한다. 고객의 재제출은 새 버전으로 연결하고 이전 의견을 보존한다.

화면에서 ‘고객 보완 대기’와 ‘운영자 검토 대기’를 구분한다. 기술 A/S와 법령·자료 검토를 분류한다. 실제 서비스 운영시간·응답 기준이 정해지기 전 임의의 24시간 대응·당일 검토 문구를 넣지 않는다.

정기 검토 결과는 기간, 확인 자료, 검토 범위, 미확인 사항, 보완 과제, 검토자·시각을 포함한다. 유료 계약과 연결하며, 사람이 검토하지 않은 AI 요약을 정기 사람 검토 결과로 보내지 않는다.

## 7. 사고 발생 화면

최초 공개 화면에는 119 구조·구급·화재와 112 경찰 연락, 검증된 짧은 공통 안내가 우선이다. 전화 버튼을 눌렀다는 이벤트를 통화·신고 완료로 표시하지 않는다. 112를 모든 산업재해의 일률적 필수 신고로 표시하지 않는다. 국가 긴급신고 체계의 출처는 [행정안전부 안내](https://www.mois.go.kr/frt/sub/a06/b10/emergencycall/screen.do)다.

공통 안내는 사전에 검토·버전 관리한 내용만 제공한다. 실시간 LLM이 의료행위나 위험한 구조 방법을 만들어 지시하지 않는다. 사용자 입력·촬영·AI 분석은 구조·대피·긴급 연락을 가로막지 않는다.

로그인 전 화면에는 저장된 고객 주소·피해자 정보를 자동 표시하지 않는다. 사용자가 직접 입력한 위치는 기본적으로 세션 내에만 둔다. 로그인 후 실제 현장 주소를 확인해 전달용 위치·동·층·진입로를 보여준다. GPS는 사용자 선택으로 참고하며 사고 장소를 자동 확정하지 않는다.

사고 기록 항목: 발생/인지 시각, 실제 위치, 확인된 피해 정보, 진행 중 조치, 관련 사업주·작업, 보고 상태. 미확정·모름을 허용한다. 상병·원인·과실을 AI가 단정하지 않는다.

보고는 법령별로 독립 카드다. 산업안전보건법상 중대재해 보고, 산업재해조사표, 그 밖의 해당 법령 보고, 산재보험 절차를 합치지 않는다. 실제 조건·서식·기한은 승인된 규칙으로만 제공한다. 이 문서에 그 모든 법적 조건이 검증되어 들어 있는 것은 아니다.

관할은 실제 장소·업무·책임 주체에 맞춰 공식 기준으로 확인한다. 가장 가까운 관서나 본사 관서로 자동 결정하지 않는다. 부서·업무·연락처·주야간·공식 출처·확인일을 저장하고, 미확인이면 [고용노동부 관할관서찾기](https://www.moel.go.kr/minwon/rigion/rigion_C1.do) 등 공식 경로를 제공한다. 일반 상담 번호를 사고 보고 담당 번호로 바꾸지 않는다.

오프라인 제공은 이전에 내려받은 공개 안내만 대상으로 한다. 첫 방문·캐시 삭제·전화 통신 불가 등 제한을 설명한다. 인증 자료·건강정보·비공개 PDF를 서비스워커에 일괄 저장하지 않는다.

## 8. JH 관제 화면

‘오늘 처리할 일’은 중요 보완, 기한 임박/경과, 신규 사실 확인, 재제출, 정기 검토, 상담, 규칙·연락처 갱신으로 나눈다. 사고 관련 문의를 위에 표시할 수 있지만 관제가 긴급기관 역할을 한다고 표현하지 않는다.

고객 상세에는 현재 사실 스냅샷·적용 의무·업로드·미확인·최종 검토일을 보여준다. 자료 검토에서는 원본, 기존 버전, AI 제안, 근거, 고객 공개 의견과 내부 메모를 구분한다. 내부 메모는 고객 API·내보내기·AI 요약에서도 노출하지 않는다.

배정·배정 취소·지원 기간·민감자료 권한·추가 인증을 반영한다. 법령 관리 화면의 승인·배포는 고객 검토 버튼과 분리한다. 관리자 화면을 숨기는 것 외에 서버 권한 검증을 구현한다.

## 9. 데모 시나리오

가상 사례: 직원 없는 점포, 4명 음식점, 5명 편의점, 20명 시설관리업, 50명 제조업, 500명 이상 다사업장 기업, 이동 작업/건설 현장. 숫자는 UI·데이터 표현 시험용이며 법정 의무가 그 숫자에서 생긴다는 의미가 아니다.

반드시 포함할 흐름: A고객 제출 → 배정된 JH 검토 → 보완 요청 → A고객 재제출 → 검토 이력 → B고객에서는 A자료 접근 불가. P1에서는 권한 동작이 데모임을 표시하고, 실제 접근 차단은 P2에서 별도로 검증한다.
