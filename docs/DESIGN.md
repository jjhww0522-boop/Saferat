# Saferat 디자인 기준

2026-09-15 · 사용자 확정 계획: 중앙관제 진입 분리, 사업장별 업무 목록과 전체 후보 열람, 전체 공통 기록 + 핵심 자체 서식. 균형안을 바탕으로 구현한다.

## 1. 적용 상태와 문서 우선순위

- 2026-09-21 사용자 선택 확정: **모바일 현장 사용 우선, 단계 안내 + 전체 지도**. 작은 화면의 한 가지 행동·입력·저장·재개와 현재 위치 확인을 먼저 설계하고 PC로 확장한다. 시설관리 사업장을 첫 검증 대상으로 한다. 실제 기기의 가상 키보드·한 손 조작·현장 네트워크 검증은 브라우저 반응형 검사와 별도로 남긴다.

- 2026-09-18 추가 가독성 요청: 사용자가 [시각적 설명 방식 토론](plans/2026-09-18-visual-readability-review.md)에 “계획대로 진행해봐”로 승인했다. 벤토 요약 홈·설명형 작업 화면·자료 목록을 구현하고 Pretendard 실제 공급·역할별 글자 크기·밝은 회백 바탕·네이비 글자·파란 주 행동을 적용한다. 검증은 `PROGRESS.md`를 따른다. 아래 크림·코랄·명조 결정은 이전 구현 이력으로 보존하며 새 업무 화면의 제약으로 삼지 않는다.

### 2026-09-18 가독성 개편의 현재 기준

- Pretendard v1.3.9 원본 WOFF2와 OFL 1.1을 저장소에 포함하고 자체 제공한다. `next/font/local`, `display: swap`, 한국어 대체 글꼴을 사용한다. 원본 글꼴 2,057,688바이트로 첫 로딩 비용이 있으며 실제 느린 네트워크 성능은 후속 측정한다.
- 배경 `#f4f6fa`, 작업 면 `#ffffff`, 글자 `#17243b`, 본문 `#34465f`, 보조 `#53647b`, 주요 행동 `#2459cf`, 강조 상태 `#1944a1`. 주요 버튼에는 흰 글자를 사용한다. 실제 대비는 렌더링된 모든 상태에서 검사한다.
- 페이지 제목 PC32px/모바일28px, 주 행동 PC34px/모바일28px, 질문 PC28px/모바일26px, 본문17~18px, 입력·레이블17px, 저장 상태15~16px, 보조정보14px 이상을 기본으로 한다. 기존 문서의 더 작은 수치는 새 안내 화면의 기준이 아니다.
- 홈은 다음 행동이 가장 큰 벤토 영역이며, 실제 남은 확인이 없으면 세 번째 카드를 만들지 않는다. 저장 기록은 목록으로 제공하고 최신순이 보장되지 않는 목록을 ‘최근 자료’라고 부르지 않는다.
- 설명용 SVG와 수동 3컷 도움은 실제 입력/문서/완료 상태를 만들지 않는다. 필수 설명은 HTML 문구로 제공한다. 실제 폼은 유지하고 설명 장면만 전환한다.
- 모바일은 단일 열, 미시작 지도 업무는 펼침, 폼 저장 상태는 스크롤 중에도 볼 수 있게 한다. 짧은 전환은 모션 감소에서 제거하고 포커스가 상태 막대에 가려지지 않도록 이동 여백을 둔다.

### 이전 구현의 결정 이력

- 2026-09-18 안내 UX 요구는 능동 안내·전체 지도·중요 업무 강조를 포함한 큰 UX 개편이다. 아래 2026-09-17의 ‘최대 3행·큰 카드 추가 금지’는 당시 구현 범위이며 새 개편의 제약으로 사용하지 않는다. [검토안](plans/2026-09-18-guided-safety-journey-design.md)은 한 가지 중심 행동, 짧은 단계, 관계도, 도움말 패널, 저장 결과 전환을 제안했다. 당시 크림·코랄을 기반으로 사용자 승인 후 구현했으며 검증 결과는 `PROGRESS.md`에 기록한다.

- 2026-09-17: 다음 행동은 기존 크림·코랄 목록 안에서 최대 3행과 남은 수·펼침으로 보여준다. 큰 카드나 위험 점수 대시보드를 추가하지 않는다. 관리체계의 인력·예산·의견·도급·이행점검은 초기 진입에서 찾을 수 있어야 한다. 입력과 저장본은 제목·상태·구분선으로 구분한다. [승인 개선 계획](plans/2026-09-17-next-actions-design.md) 참조.

- 모든 업무 화면에 [초보자 중심 서비스 핵심 원칙](BEGINNER_SERVICE_PRINCIPLES.md)을 적용한다. 첫 행동과 실제 입력·증빙을 먼저, 상세 안내·공식 매뉴얼·근거 조문을 필요할 때 펼친다. 전문성은 초보자도 수행 순서와 미확인 상태를 이해할 수 있는 구조로 드러낸다.
- 위험성평가처럼 여러 활동이 연결되는 업무는 단계 탐색과 부분 저장을 제공한다. 진행 표시는 ‘기록 갖춤’으로 표현하고 법적 완료·현장 안전과 혼동시키지 않는다. 긴 카드의 반복보다 구분선·단정한 정렬을 사용한다.

- 랜딩 회전 제거에 이어 코랄·크림 색상, 큰 제목의 세리프, 수평 두 열 랜딩, 회원 업무 목록·기록 화면을 구현한다. 실제 검수 결과와 미검증 범위는 `PROGRESS.md`를 따른다.
- 사용자 최신 지시 → 제공 원본 `../DESIGN-claude.md` → 이 문서의 명시된 제품별 조정 순서로 판단한다. 원본을 단순 참고 자료로 낮추거나 새 색상·장식을 임의로 추가하지 않는다.
- 확정 사항: 업무 카드의 장식용 회전 금지, 원본과의 차이 공개, 실제 상태·권한·접근성 보존. 원본을 변경해야 할 때는 대상·이유·대안을 기록한다.
- 아래 B안을 확정된 구현 계획의 시각 기준으로 사용한다. 사용자 선택과 대표 화면 검수 결과는 `DECISIONS.md`와 `PROGRESS.md`에 남긴다. 이전 검토 제안과 실행 결과를 구분한다.
- 하단 P1 기록은 과거의 결정을 보존한 자료다. 당시의 파란 강조색·전면 고딕체 사용을 향후 화면의 기본값으로 확대하지 않는다.

## 2. 검토한 방향

| 방향 | 적용 방식 | 장점과 한계 |
|---|---|---|
| A. 원본에 가까운 소개 화면 | 코랄·세리프·큰 여백·크림과 어두운 구획의 교차를 적극 적용 | 원본과의 일치도가 높지만 반복 업무 화면까지 적용하면 정보 탐색이 느려질 수 있다 |
| **B. 기업 브랜드와 업무 가독성의 균형 — 추천** | 소개 화면은 원본의 편집 구조, 업무 화면은 같은 색상과 글꼴 체계 안에서 목록·양식 중심 | 서비스의 인상을 유지하면서 현장 업무를 빠르게 처리할 수 있다. 두 화면의 공통 토큰 관리가 필요하다 |
| C. 업무 중심의 절제된 화면 | 같은 브랜드 색상에 작은 제목과 높은 정보 밀도, 표·구분선 중심 | 반복 작업에는 효율적이지만 첫 화면에서 서비스의 개성과 설명력이 약해질 수 있다 |

전문성의 판단 기준은 장식의 양이 아니라 정보의 우선순위, 일정한 정렬, 정교한 한글 조판, 상태의 정확성이다. 특정 도구로 만들었는지는 외관만으로 판정하지 않는다.

## 3. 채택한 색상 규칙

| 역할 | 값 | 사용 원칙 |
|---|---|---|
| 기본 배경 | `#faf9f5` | 원본의 따뜻한 크림 유지 |
| 보조 면 | `#efe9de` | 묶음·선택 영역에 제한적으로 사용 |
| 본문·어두운 구획 | `#181715` | 원본 토큰 사용. 어두운 구획을 업무 화면 전체에 반복하지 않음 |
| 브랜드 코랄 | `#cc785c` | 주요 CTA와 필요한 브랜드 강조에 사용 |
| 짙은 코랄 | `#a9583e` | 작은 링크·활성 상태에 사용 |
| 보조 글자 | `#646159` | 작은 설명에 적용. 실제 배경 조합별 대비 확인 |
| 위험·보완·검토 상태 | 의미별 토큰 | 브랜드 장식과 분리. 항상 상태명과 함께 표시하고 기존 업무 의미를 유지 |

원본의 코랄 위 흰 글자는 대비 약 3.277:1이다. 일반 텍스트의 4.5:1 기준에 부족하므로 기본 CTA는 **코랄 배경 + 짙은 글자 `#181715`**를 사용한다(약 5.467:1). 흰 글자가 필요한 경우 짙은 코랄 배경과 조합한다(약 5.057:1). 짙은 코랄 링크/크림 배경은 약 4.800:1이다. `#efe9de` 보조 면에서는 `#a9583e` 링크가 약 4.18:1로 부족해 더 짙은 `#89432e`를 사용한다. 이는 원본의 색상 계열을 유지하기 위한 명시적 접근성 조정이다.

수치는 sRGB 상대 휘도로 계산했다. 최종 렌더링의 크기·굵기·배경·상호작용 상태를 다시 확인하며, 소수점 반올림으로 기준 통과를 판정하지 않는다. 기준 출처: [W3C 텍스트 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

파란색을 기본 브랜드 강조로 쓰지 않는다. 보라색 그라데이션이나 별도의 장식 색상 체계를 도입하지 않는다. 경고색이 브랜드 색상으로 오인되지 않도록 아이콘·문구·위치를 함께 설계한다.

## 4. 타이포그래피·간격

- 원본의 큰 제목은 세리프, 본문·입력·탐색은 산세리프라는 역할 분리를 유지한다. 한글 제목은 한글을 지원하는 명조 계열을 실제 문장으로 비교하고 선택한다. 영문 전용 폰트 이름만 지정해 한글이 임의의 폰트로 표시되는 것을 피한다.
- 글꼴 선택 시 사용 권한·한글 지원·필요한 굵기를 확인한다. 새 파일을 배포할 때는 승인된 파일을 자체 호스팅하고 대체 글꼴을 지정한다. 현재는 시스템의 한글 명조 계열 대체 글꼴을 사용하며 외부 폰트 설치·배포는 하지 않았다.
- 소개 화면의 h1은 데스크톱 48~64px, 모바일 32~36px 범위에서 실제 문장 길이로 조정한다. 세리프 제목은 보통 굵기로 시작하며, 한글에 영문용 음수 자간을 일괄 적용하지 않는다.
- 업무 화면 제목은 24~28px, 본문·입력은 16px, 보조 정보는 14px을 기본으로 한다. 읽어야 하는 상태·기한을 11px로 축소하지 않는다. 줄 높이는 본문 1.5~1.7을 기준으로 확인한다.
- 간격은 4/8/12/16/24/32/48/64/96px 단위를 사용한다. 소개 구획은 데스크톱 96px, 모바일 48~64px을 기본으로 하고, 업무 화면의 같은 그룹은 16~24px로 묶는다.
- 모서리는 입력·버튼 8px, 업무 카드 12px, 대표 시연 영역 16px로 제한한다. 그림자는 떠 있는 메뉴처럼 실제 레이어 구분이 필요한 곳에서만 사용하고, 일상적인 구획은 여백·얇은 선으로 나눈다.

## 5. 소개 화면과 업무 화면

현재 구현 우선순위: 공개 화면에 중앙관제 진입을 표시하지 않는다. 회원 홈은 현장 선택 → 간단한 기한·보완 요약 → 분야별 업무 목록 순서다. ‘전체 후보 열람’을 제공하고, 기존의 큰 다음 행동 카드보다 목록을 우선한다. 후보 등록은 적용 확정이 아니며 자료·수행·검토·접수 상태를 분리한다.

### 소개 화면

- 데스크톱은 최대 1200px 안에서 원본의 6:6 두 열 구조를 사용한다. 왼쪽에는 서비스 설명과 주요 행동, 오른쪽에는 수평으로 정렬된 실제 업무 흐름 예시를 둔다. 모바일에서는 설명 다음에 예시를 배치한다.
- 주제는 사업장 사실 확인 → 해야 할 일 → 자료 준비 → 검토·보완이다. 추상적인 기술 홍보 대신 담당자가 무엇을 할 수 있는지 설명한다.
- 업무 예시는 실제 앱과 같은 상태·명칭·정보 순서를 사용한다. 정지된 예시와 누를 수 있는 버튼을 구분한다. 데모임을 표시하며 실제 고객 자료나 확인하지 않은 실적 수치를 넣지 않는다.
- 소개·업무 흐름·사람 검토의 범위를 설명하는 데 필요한 구획만 만든다. 어두운 구획은 검토 과정 등 강조할 내용이 있을 때 사용하며, 화면을 채우기 위해 같은 카드 3개를 반복하지 않는다.
- 공개 긴급 연락, 체험, 회원 진입이 각자의 목적에 맞게 구분되어야 한다. 주요 행동은 한 구획 안에서 시각적으로 하나가 우선한다.

### 업무 화면

- 회원 홈은 간단한 목표일·보완 요약 → 분야별 업무 목록 → 항목별 확인·기록 순서다. 관련 업무는 행과 구분선으로 정리하며 분야를 기본 펼침으로 보여준다.
- 업무 행의 순서는 업무명 → 현재 상태 → 담당·확인된 일정 → 다음 행동을 기본으로 한다. 확인되지 않은 기한·담당자는 만들어 넣지 않는다.
- 자료와 사람 검토에서는 버전, 보완 위치, 요청 내용, 재제출 여부를 쉽게 비교할 수 있게 한다. 수치는 실제 기록의 개수에만 사용한다. 법적 준수율·안전 점수는 만들지 않는다.
- 모바일 하단 탐색과 긴급 접근, 운영자의 배정 범위 등 기존 사용자 흐름을 보존한다. 선택한 상태와 키보드 포커스가 동시에 구분되어야 한다.

## 6. 장식·문구·상태 규칙

- 업무 카드·양식·표를 기울이거나 겹쳐 놓지 않는다. 블러 배경, 과도한 광택, 커서 장식, 자동으로 떠다니는 요소는 사용하지 않는다.
- 정렬을 깨는 요소에는 정보상 이유가 있어야 한다. 모든 내용에 테두리·그림자·아이콘·배지를 동시에 붙이지 않는다. 아이콘은 이동·행동·상태를 설명할 때만 사용한다.
- 원본에 없는 이동·확대 hover 효과나 장식용 진입 애니메이션을 추가하지 않는다. 필요한 상태 변화는 눈에 거슬리지 않게 표시하고 reduced-motion을 존중한다.
- 긴 한국어 제목, 두 줄 상태명, 빈 값, 큰 글씨에서도 정렬이 유지되어야 한다. 날짜·숫자는 같은 열에서 일관되게 정렬한다.
- 초안, 내용 확인, 실제 수행, 검토 대기, 보완 요청, 자료 검토 완료, 기관 접수 미확인을 서로 바꾸어 표현하지 않는다.
- 저장 중·실패·권한 없음·빈 목록은 화면 설계에 포함한다. 실제로 가능한 다음 행동을 안내하고, 실패 시 입력을 보존한다. 내부 기술 이름은 회원의 판단에 필요한 경우에만 노출한다.
- 가상의 고객 로고·후기·인증·안전 성과를 만들어 신뢰를 연출하지 않는다. 사진은 내용상 필요하고 사용 권한이 확인된 경우에만 사용한다.

## 7. 화면 검수와 적용 절차

1. 디자인 방향 선택과 원본 대비 변경표 확인 → 색상·글꼴·레이아웃의 기준을 기록한다.
2. 랜딩 / 회원 업무 목록 / 자료 상세·검토의 대표 화면부터 적용한다. 각각 데스크톱과 모바일로 확인하고 토큰·공통 요소를 조정한다.
3. 320/360/768/1440px에서 가로 넘침, 글자 겹침, 줄바꿈, 버튼·오류 상태를 확인한다. 주요 조작은 프로젝트 기준 48px 높이를 유지한다.
4. 대비 검사, 보이는 키보드 포커스, 입력 레이블, 200% 확대를 확인한다. 자동 접근성 검사는 육안·키보드 검사를 대체하지 않는다.
5. 정보 확인 → 자료 준비 → 보완 → 재제출의 기존 브라우저 시나리오를 실행한다. 스크린샷이 정상이어도 업무 상태가 달라지면 완료가 아니다.
6. 실제 현장 담당자의 첫 행동 선택·미확인/완료 이해·막힌 지점을 확인한다. 사용자 참여 검증은 현재 미실행이다.
7. 대표 화면에서 확인된 규칙을 나머지 화면에 확장하고 `PROGRESS.md`에 변경·실행·미검증 항목을 남긴다.

# 사업장 정보 선입력 원칙 · 2026-09-15

- 등록정보·분류·인원 입력은 관리 업무와 동등한 행으로 나열하지 않는다. 초기 진입에는 입력 순서와 현재 단계, 다음 행동을 먼저 보여준다.
- 네 단계(등록정보, 업종·실제 작업, 인원·고용관계, 입력 확인)를 일정한 정렬·간격으로 제공한다. 마지막 확인 뒤 관련 업무 목록을 표시한다.
- 목록에는 저장한 사업장 정보 요약과 변경 동선을 제공한다. 미확인 정보는 추가 질문으로 묶어 표시하며 긴급 업무 색상과 구분한다.
- 사진·계획 등 범용 기록 도구는 업무 목록 아래 보조 동선으로 둔다. 자료·수행·검토 상태와 조문 안내는 각 업무에 유지한다.
