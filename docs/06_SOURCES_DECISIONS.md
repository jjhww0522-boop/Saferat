# 06. 출처·확인 범위·미결 사항

작성일: 2026-09-14. 출처가 존재한다는 사실, 본문을 읽은 범위, 법적 적용을 검토한 상태를 구분한다. 이 묶음은 법령 전수 검토 결과가 아니다.

## 1. 요구사항의 근거

주요 제품 요구는 이 대화에서 사용자가 정한 내용이다: 전 산업·전 규모, 현장 담당자 중심, 법적 의무와 근거, 사업자등록증 OCR, 증빙·자동 작성·AI 보완, JH 중앙 관제, 유료 정기 사람 검토 포함, 온라인 우선, 무료 회원 확보 후 광고·기업 구독, 개발 후 등록, 잠정 월 50만 원·약 1년.

기존 자료 중 다음 세 문서의 본문을 확인하고 통합했다. 개발 묶음은 이들 파일을 별도로 내려받지 않아도 사용할 수 있도록 작성했다.

- `safety_service_product_requirements_v1.md`: 완결된 회원 경험, 법령 조사·의무 원장, 제품 합격 기준.
- `industry_rules_incident_response_spec.md`: 업종·규모·작업 분류, 사고·관할·보고, 1인 검토 운영.
- `operations_ocr_implementation_spec.md`: 운영자 배정·검토·보완과 등록증 OCR·권한 구분.

과거 기획의 83개 후보 항목은 완전한 법령 목록으로 가져오지 않았다. 과거 문서의 개별 법령 사례를 이 묶음에서 승인된 실행 규칙으로 변환하지 않았다. 실제 적용을 구현할 때 해당 시점의 공식 원문을 다시 확인한다.

## 4. 외부 연계 출발점

- [국세청 사업자등록정보 진위확인·상태조회 API](https://www.data.go.kr/data/15081808/openapi.do): 기존 OCR 명세의 연동 후보. 실제 연동 시 최신 요청/응답·이용조건을 확인한다. 사업자 상태와 가입자 권한을 혼동하지 않는다.
- [CLOVA General OCR 공식 문서](https://api.ncloud-docs.com/docs/ai-application-service-ocr-ocr): OCR 공급자 후보 참고. 필수 채택·가격·정확도를 확정하지 않았다.
- [고용노동부 노동포털 산업재해조사표 경로](https://labor.moel.go.kr/minwonApply/minwonFormat.do?searchGubun=1&searchRlm=2&searchVal=AH038): 기존 사고 명세의 참고 경로. 실제 서식·접수 방법은 출시 시 확인한다.

행정기관 자동 제출 API가 있다고 가정하지 않는다. 공식 안내와 제출본·접수증 관리만으로 시작할 수 있다. 지원사업은 별도 사업 분석 과제이며 앱 구독료 지원 가능 여부를 이 문서에서 확정하지 않는다.

## 5. 개발 결정을 기록하는 기준

선택한 값은 `확정 요구 / 개발 가정 / 운영 정책 / 검토 대기 / 폐기` 중 하나로 기록한다. 개발 기본값을 법정 기준 또는 사용자 확정 조건으로 승격시키지 않는다.

| 미결 항목 | 지금 개발할 때의 기본 처리 | 확정 시점 |
|---|---|---|
| 서비스명·도메인 | ‘사업장 안전관리’ 작업명, 브랜드 파일 분리 | 공개 전 |
| 기존 저장소·Orca 버전 | 실제 환경 먼저 확인, 전용 기능 가정하지 않음 | P0 |
| 주당 개발 시간 | 단계·완료 기준 중심, 일정 보장 없음 | 일정 세분화 때 |
| 월 예산의 기존 구독료 포함 여부 | 월 50만 원 잠정 상한, 실제 사용량 기록 | 유료 자원 연결 전 |
| 무료 기준·AI/파일 한도 | 운영 설정으로 분리, 임의의 인원 기준 고정 금지 | 베타 이용 정책 전 |
| 유료 가격·사람 검토 주기·분량 | 유료 검토 포함 원칙, 구체 SLA는 미설정 | 유료 판매 전 |
| 법령·안전·개인정보 검토자 | 검토 대기와 범위 표시, 에이전트 자체 승인 금지 | 해당 실제 기능 공개 전 |
| 시험 사용자·제휴기관 | 가상 데이터로 개발, 외부 발송 없음 | 비공개 시범 운영 전 |
| 공급자·리전·보존·국외 처리 | 연결부만 준비, 실제 계약조건 확인 | 실사용 원문 처리 전 |
| 재직 중 사업화·사업자등록 | 운영 준비 항목으로 기록, 개발 범위와 구분 | 공개 운영·광고·판매 계획 확정 전 |

공기업·준정부기관 영리업무·겸직 제한의 공개 근거는 [공공기관운영법 제37조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1017473763)다. 앞선 논의에서 조문을 확인했으며, JH의 구체적인 허용 범위·공사 내규는 확인되지 않았다. 본 문서가 영리 운영 가능 확인서가 되는 것은 아니다.

## 6. 출처 레코드에 남길 필드

`id / title / publisher / official_url / document_version / published_at / effective_from_to / fetched_at / content_hash / checked_scope / checked_by / check_status / related_rule_ids / next_review_reason`

원문 URL 도달, 내용 수집, 내용 검토, 규칙 승인, 운영 배포는 독립 상태다. URL 검사 성공을 법적 검증 완료로 표시하지 않는다. 확인되지 않은 필드는 null과 확인 필요 사유로 남긴다.

## 7. 개발하면서 결정할 세 질문

1. 첫 시험 사용자에게 가장 먼저 끝까지 해결해 줄 업무는 무엇인가: 의무 확인, 사진 점검대장, 문서 보완 중 어디에서 불편이 가장 큰가?
2. JH가 월간 사람 검토에 쓸 수 있는 시간으로 어느 정도 고객 수와 검토 범위를 감당할 수 있는가?
3. 다음 업종·법령을 추가할 때 어떤 공식 근거·검토자·기대 사례가 확보되어야 실제 자동 판정을 공개할 것인가?

이 질문은 최초 데모 개발을 중단시키는 조건이 아니다. 가상 자료와 명시적 개발 기본값으로 구현을 시작하고 실제 고객 공개 범위를 정할 때 답한다.
