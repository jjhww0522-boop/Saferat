# 04. 기술 구성·AI·보안·비용

작성일: 2026-09-14. 기술 구성은 신규 프로젝트용 제안이다. 실제 버전·요금·리전·계약조건은 연결 시 공식 자료로 확인한다. 특정 유료 상품 구매나 외부 배포 승인은 포함하지 않는다.

## 1. 단순한 구성부터 시작

| 영역 | 신규 프로젝트 기본안 | 이유/대안 |
|---|---|---|
| 화면·서버 | Next.js App Router + TypeScript | 한 저장소에서 회원·운영자·서버 처리. 기존 기술이 있으면 보존 |
| 스타일 | Tailwind CSS, 필요할 때 shadcn/ui | 일관된 기본 컴포넌트. 과도한 라이브러리 추가 금지 |
| 데이터·인증·파일 | PostgreSQL + Supabase Auth/Storage | 관계 데이터와 접근 정책을 함께 관리. 연결부를 분리해 이전 가능하게 |
| 입력 | 서버 스키마 검증, 필요 시 Zod | 브라우저 값을 신뢰하지 않음 |
| 규칙 | 별도 TypeScript 도메인 모듈, 버전 있는 JSON AST | LLM과 독립적으로 결과·근거 재현 |
| 문서 | 검토된 템플릿 + HTML 미리보기, PDF 생성 연결부 | 한글 폰트·페이지 분리·표 넘침·첨부 위치 검증 |
| AI/OCR | 공급자 중립 서버 연결부 | 가격·데이터 처리조건에 따라 교체. 초기 mock/off 가능 |
| 백그라운드 작업 | DB 작업 큐 + 제한된 워커/스케줄 | OCR·PDF·재평가·알림을 재시도 가능하게 |
| 검증 | 도메인 단위 테스트, DB 권한 통합 테스트, 핵심 흐름 E2E | 구현에 맞는 도구 선택·버전 고정 |

단일 저장소·단일 앱부터 시작한다. 마이크로서비스·별도 벡터 DB·모바일 네이티브 앱을 시작 조건으로 삼지 않는다. 다만 도메인 규칙·저장·AI 인터페이스는 분리해 UI와 법령 규칙이 서로 하드코딩되지 않게 한다.

소스 폴더 제안: `src/app`, `src/components`, `src/domain`, `src/server`, `src/adapters`, `src/demo`, `supabase/migrations`, `tests`, `docs`. 프로젝트가 이미 있으면 같은 개념을 기존 구조에 맞춘다.

## 2. 실행 모드와 실제 데이터

| 설정 | 동작 |
|---|---|
| `APP_MODE=demo` | 가상 고객·가상 자료·시험용 규칙. 실제 계정/개인정보 입력 금지 안내 |
| `APP_MODE=live` | 실제 인증·권한·비공개 저장 필수. 설정 누락 시 명시적 실패 |
| `AI_MODE=off/mock/live` | 미연결·데모·실제 처리 표시를 구분. 운영 환경 mock 응답을 실제 결과로 표시 금지 |
| `OCR_MODE=off/mock/live` | 수동 입력 유지, 원문·후보·확정값 분리 |

이 변수명은 앱이 구현할 자체 설정 계약이다. Orca나 공급자가 제공하는 내장 옵션이라고 설명하지 않는다. 운영 서버에서 환경변수·쿼리 문자열·브라우저 저장값으로 권한을 우회할 수 없게 한다.

P1은 메모리/로컬 시험 저장소로 동작해도 된다. 데모 회원·운영자 화면은 동일 저장소를 공유하고 새로고침 유지 여부와 초기화 동작을 설명한다. P2 이후 실사용 자료는 브라우저 localStorage/IndexedDB만으로 보관하지 않는다. 데모 로그인·역할 전환 경로는 실제 인증 경로와 격리한다.

## 3. 인증·인가·데이터 경계

모든 읽기·쓰기·다운로드·서버 액션에서 세션과 자원 권한을 확인한다. Next.js 공식 문서도 서버 액션을 외부에서 직접 호출 가능한 진입점으로 보고 각 액션 내부 인증·인가를 요구한다. [Next.js Data Security](https://nextjs.org/docs/app/guides/data-security)

구현 요구:

- 세션 사용자 → 활성 조직 소속 → 현장 접근 → 해당 자원의 작업 권한 순서로 확인한다.
- tenant_id·workplace_id·role을 요청 본문에 넣었다고 권한을 주지 않는다. 실제 자원 소속과 서버 조회 결과를 대조한다.
- 사용자 편집 가능한 프로필 메타데이터를 관리자 권한 근거로 사용하지 않는다.
- PostgreSQL RLS와 최소 테이블 권한을 함께 적용한다. select/insert/update/delete를 각각 시험한다. 뷰·RPC·보안 정의 함수의 우회 경로도 확인한다. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)
- 검색·집계·내보내기·알림·백그라운드 작업에도 같은 범위를 적용한다. 행 개수나 오류로 다른 고객 존재를 불필요하게 노출하지 않는다.
- 운영자 원문 접근은 유효한 업무 배정·범위·기간과 추가 인증을 확인한다. 부여·철회·열람·다운로드를 기록한다.
- 민감자료 접근은 일반 현장 담당자 권한과 분리한다. 피해자 건강자료의 본문·썸네일·파일명도 보호한다.
- 원문을 열기 전에 감사 기록을 남기는 서버 경로를 사용한다. 운영자 브라우저에 서비스 관리자 키를 주지 않는다.

서비스 키는 RLS를 우회하므로 ‘서버에서 호출하니까 안전’이라고 간주하지 않는다. 필요한 관리·워커 경로에만 두고 작업별 고객·자원 범위를 다시 확인한다. 파일 저장소에도 별도 접근 정책이 필요하다. [Supabase Storage Access Control](https://supabase.com/docs/guides/storage/security/access-control)

## 4. 파일 처리

1. 업로드 요청의 고객·현장·의무 권한을 확인한다.
2. 파일 크기·페이지 수·확장자·실제 MIME/시그니처를 검사한다. 암호화 PDF·손상 파일·지원하지 않는 형식은 정확한 사유와 대안을 제공한다.
3. 비공개 격리 저장소에 저장하고 해시를 계산한다. 실제 이용자 파일은 악성 파일 검사 상태를 확인하기 전 미리보기·OCR 작업에 사용하지 않는다.
4. 파싱·렌더링 작업은 제한된 시간·메모리·네트워크 권한에서 수행한다. 문서에 들어 있는 URL을 자동 방문하지 않는다.
5. 원본, 미리보기, 주석본, 출력본을 별도 객체로 보존하고 접근권한을 각각 적용한다.
6. AI 처리 전 필요한 페이지·영역만 선택하고 불필요한 개인정보를 줄인다.

원본 접근은 기본적으로 서버 권한 확인을 거친 스트리밍/다운로드 경로로 제공한다. 단기 서명 URL을 사용할 경우 URL이 유효한 동안 전달 가능한 토큰임을 전제로 만료·로그 제외·캐시 제한을 설계한다. 민감자료는 철회 가능한 서버 경로를 우선한다. 기존 파일 URL을 알고 있어도 고객·배정 권한 철회 후 새 접근이 허용되지 않도록 검증한다.

개인자료는 공개 CDN/서비스워커에 캐시하지 않는다. 외부로 내보낼 파일에도 내부 메모·비공개 데이터가 섞이지 않게 한다. 파일 해시는 변경 감지용이며 공인 시점 인증이나 증거 진실성 보증을 뜻하지 않는다.

## 5. OCR 연결부

인터페이스 제안: `extractRegistration(documentVersionId)`, `confirmFields(extractionId, confirmedValues)`. 입력 파일 ID마다 권한을 다시 확인한다. OCR 결과에는 필드명·원문값·정규화 후보·페이지/좌표·문자 신뢰도·처리 버전을 둔다.

등록정보 대조를 연결하면 별도 `verifyBusinessRegistration` 작업으로 만든다. 응답 일치/불일치/조회 실패/미지원은 구분한다. 사업자번호만으로 전체 정보나 소속 권한을 확인할 수 있다고 가정하지 않는다. 실제 연동은 [국세청 API 공식 명세](https://www.data.go.kr/data/15081808/openapi.do)의 요청 필드·이용조건을 확인한 뒤 구현한다.

## 6. AI 보완·문서 작성 연결부

입력은 권한 있는 문서 버전, 관련 의무의 승인된 요구사항, 사용자 확정 사실로 제한한다. 고객 자료를 모든 조직이 공유하는 검색 인덱스에 넣지 않는다. 검색이 필요하면 고객·현장·문서 버전·민감도 권한을 조회 전과 결과 반환 전에 검증한다.

출력 구조 제안:

```ts
interface Finding {
  category: 'missing' | 'inconsistent' | 'unreadable' | 'needs_confirmation' | 'suggestion';
  requirementId?: string;
  documentVersionId: string;
  evidence: { page?: number; field?: string; region?: number[]; excerpt?: string }[];
  explanation: string;
  suggestedAction: string;
  legalSourceIds: string[];
  requiresHumanReview: boolean;
}
```

출력 JSON 스키마와 근거 ID를 검증하고 존재하지 않는 조항·페이지·관찰 근거를 반환하면 표시를 보류한다. `적법/위법` 단일 판정이나 AI가 생성한 적합도 숫자를 최종 결과로 쓰지 않는다. 단순 누락과 실제 상황 확인 필요를 구별한다.

업로드 파일·이미지 속 지시는 간접 프롬프트 주입 경로가 될 수 있다. 입력 구분만으로 해결됐다고 보지 말고, 모델에 임의 SQL·네트워크·메일·권한 변경 도구를 주지 않으며 서버 출력 검증과 실제 행위 권한을 적용한다. [OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

문서 생성은 검토된 서식·필수 필드에 확인된 사실만 매핑한다. ‘작성자 결정 필요’ 값은 사용자에게 묻거나 빈칸으로 남긴다. 확인 화면 없이 확정 사실·법령 규칙·외부 제출 상태를 바꾸지 않는다.

모든 작업에 tenant, 문서 버전, 모델/프롬프트/요구사항 버전, 실행 시각, 사용량, 결과 상태를 기록한다. 일반 로그에는 원문·비밀값·서명 URL을 넣지 않는다. OCR·AI 오류 시 수동 입력·기존 업무·사고 안내는 유지한다.

## 7. 비용·재시도·백그라운드 작업

- 고객·기능·기간별 사용량 원장과 플랫폼 전체 월 상한을 둔다. 상한은 실제 가격이 아니라 운영 설정이다.
- 동시 요청에 대비해 호출 전에 예상 비용/회수 한도를 원자적으로 예약하고, 완료 후 실사용으로 정산한다. 단순 ‘조회 후 증가’ 방식의 경합을 방지한다.
- 토큰·사진 크기·페이지 수·응답 길이·재시도 횟수·동시 실행 수에 서버 한도를 둔다.
- 작업 상태는 queued/running/succeeded/failed/cancelled로 저장하고 재시도·중복 이벤트를 처리한다. 같은 문서·같은 작업의 중복 과금 방지를 위한 멱등 키를 둔다.
- 제공업체 호출이 실제 발생한 실패는 과금될 수 있으므로 사용량을 무조건 0으로 되돌리지 않는다. 예약 해제와 실제 비용은 분리한다.
- 웹 응답이 끝난 후 유지된다는 보장이 없는 프로세스에 중요한 작업을 맡기지 않는다. 배포 환경에 맞는 워커·스케줄과 재시도 계약을 구현한다.
- 결제·광고·정부지원 연계가 없으면 설정을 비활성화하고 가상 매출을 실제 수익으로 집계하지 않는다.

## 8. 개인정보·보존·복구

개인정보 항목·목적·처리 근거·처리 역할·제공/위탁·보존기간·국외 처리 여부·수신 공급자를 데이터 흐름 표로 만든다. 공급자의 실제 계약·데이터 보관·학습 이용·리전·삭제 기능을 확인한 뒤 실사용 키를 연결한다. 한국 리전을 골랐다는 사실만으로 모든 AI 데이터 이동이 국내라고 표시하지 않는다.

원칙적으로 주민등록번호는 수집하지 않는다. 건강·사고 자료는 필요한 업무에서만 별도 접근 범위를 둔다. 처리방침·위탁 계약·관련 동의는 실제 운영에 맞춰 검토해야 하며, AI가 작성한 문서를 법률 검토 완료로 표시하지 않는다. 검토 출발점은 개인정보 보호법과 하위 규정이며 출처 원장은 `06_SOURCES_DECISIONS.md`에 있다.

보존은 자료 종류·근거·기산점에 맞게 관리한다. 삭제 요청, 법정 보존, 분쟁·사고 보존 필요를 구분하고 접근 제한·보류 이유·종료 검토를 기록한다. 모든 자료를 영구보존하거나 탈퇴 즉시 무조건 삭제하는 단일 정책을 만들지 않는다.

DB와 파일 객체를 모두 백업·복구 범위에 포함한다. 데이터베이스 백업만으로 업로드 파일이 복원된다고 가정하지 않는다. 목표 복구 시점/시간은 운영 정책으로 정하고, 시범 운영 전에 실제 복구 시험 결과를 남긴다. 복구 후 이미 삭제된 자료가 다시 서비스되거나 해지된 접근권한이 살아나지 않게 한다.

## 9. 운영 구성과 외부 연동 제한

`.env.example`에는 키 이름과 설명만 제공한다. 실제 키는 로컬 비공개 설정 또는 비밀 관리 기능에 두고 저장소·브라우저·로그에서 제외한다. 회원 및 운영자 계정·개발/시험/운영 환경을 구분한다. 종속성 잠금 파일·보안 업데이트·오류 관찰을 유지한다.

기관 자동 제출·문자/메일·결제·고객 초대는 실제 연계·수신 대상·사용자 실행 행위를 확인한 기능으로만 동작한다. 초기에는 앱 내 알림과 제출 안내·증빙 기록부터 구현한다. 오류나 예산 초과 시 기능별로 안전하게 제한하고 긴급 안내를 함께 중단하지 않는다.
