# 디자인 보완과 P2 후속 계획

2026-09-15 · 카드 회전 제거와 문서 개정안 작성 완료. 전체 시각 개편과 후속 기능 개발은 아래 검토용 계획으로 구분한다.

## 현재 위치

- P0·P1: 로컬 데모와 검토 후보 탐색 구현. 실제 현장 사용성 확인은 대기.
- P2: 인증·조직/현장 권한·자료 버전·검토·비공개 격리 저장 연결부 구현. 이전 검증은 단위 86개, DB 10개, 브라우저 7개 통과이며 이번 디자인 변경 뒤 다시 실행한 결과와 구분한다.
- P2 잔여: 실제 Supabase Auth/MFA/Storage 통합 검증, 파일 검사 공급자·워커, DB와 원본 파일 복구. 운영 권한 관리·계정 복구 화면도 남아 있다.
- P3: 법령 원장·승인 규칙·활동·보고가 다음 공식 기능 단계다. 검토 후보 78개는 승인된 규칙이 아니며 실제 승인 규칙은 현재 0개다.

## 이어서 진행할 기능 작업: P2 실제 연결 마무리

### P2-A. 시험 환경 연결과 실제 권한 검증 — 우선

- 입력: 사용자가 지정한 시험용 Supabase 프로젝트와 비공개 로컬 설정. 키를 채팅에 요청하거나 기록하지 않는다.
- `../P2_SETUP.md` 순서로 마이그레이션·비공개 버킷을 설정하고, 실제 개인정보가 없는 A/B 조직·두 현장·검토자 시험 계정을 사용한다.
- 로그인·세션 갱신·MFA → 자료 초안·새 버전 → 배정 검토 → 다른 조직/현장·철회된 권한 차단을 실제 서버/API로 확인한다.
- 파일 격리 업로드, 다운로드 차단, 검사 완료 후 허용 경로를 분리해 검증한다. 파일 검사 미연결 상태를 성공으로 바꾸지 않는다.
- 완료 증거: 실제 서비스 요청 결과와 감사 기록, 실패·차단 사례. 로컬 SQL 시험 결과로 대체하지 않는다.

### P2-B. 파일 검사·복구와 남은 운영 화면

- 파일 검사 공급자와 개인정보 처리 경로를 정한 뒤 검사 워커·재시도·실패 표시를 연결한다. 구매·외부 전송이 필요한 시점에는 해당 실행 범위를 확인한다.
- 검사 전/오류/악성 결과는 계속 격리하고, 파일과 DB를 함께 복구했을 때 버전·권한·철회 상태가 보존되는지 시험한다.
- 검토자 배정·접근 철회·민감자료 권한 관리 화면은 기존 DB 권한 모델을 사용한다. 계정 복구는 실제 Auth 정책과 메일 동작을 확인한 후 연결한다.
- 계정·공급자가 없으면 설정 절차와 시험 시나리오, 키 없이 만들 수 있는 화면·계약 검증을 진행한다. 실제 연결 대기는 계속 별도로 표시한다.

## 그다음 공식 단계: P3

1. 시설관리·유지보수 범위부터 출처·시행일·예외·필요한 사실을 원장에 구조화한다.
2. 규칙 초안 → 검토 의견 → 승인/배포 권한 → 버전·철회·개정 영향 화면과 서버 동작을 구현한다.
3. 미응답·경계값·예외·시행일의 기대 사례를 고정하고 전문 검토를 연결한다. 검토 전에는 자동 법적 판정으로 제공하지 않는다.

P2 외부 연결이 대기하는 동안 P3 원장·검토 흐름의 기술 준비는 가능하다. 이 경우에도 P2 실사용 완료나 법령 승인 완료로 보고하지 않는다. 실제 AI/OCR·PDF는 원래 계획의 P4로 유지한다.
