# 시설관리 현장 기록과 후속 조치 · 다음 개선 검토

작성: 2026-09-21. 사용자 요청: “계속 토론해서 발전시켜봐 다음문제는 뭐야”. 제품 책임자와 디자인·개발/보안·운영 에이전트가 현재 코드를 대조하고 반론을 교환했다. 실제 고객 인터뷰·법률 전문가의 승인이 아니다. 이번 문서는 다음 구현 범위와 검증 기준이며 신규 기능 구현 완료 기록이 아니다.

## 결론

다음 제품 개선은 **시설관리에서 발견한 문제 한 건을 기록 → 조치 계획 → 실제 조치 → 재확인까지 이어가는 흐름**으로 좁힌다. 다만 개발 교차 감사에서 저장 기준의 결함 가능성이 추가로 나와 **저장 신뢰성 보강을 선행**한다. 모바일 우선·한 번에 한 가지 질문·전체 지도 기준을 유지한다.

지금 앱은 저장본과 검토 이력을 보존하지만, 일반 현장 기록의 후속 조치를 앱이 구분해서 추적하지 못한다. 자료 검토 완료를 실제 수행 완료라고 표시하지 않는 것에 더해, 실제로 남은 일을 계속 찾아갈 수 있어야 한다. 정식 서비스의 실제 인증·파일 검사·복구·승인 법령 규칙·실제 고객 검증 조건은 별도로 남는다.

## 선행 확인 · 저장 신뢰성

- **P0 · 재현·수정·브라우저 검증 완료:** 최초 입력 내용은 남아 있는데 서버 새로고침으로 hidden revision만 갱신되면, 다른 탭의 새 기록을 오래된 내용으로 다시 저장할 수 있는 코드 경로가 있다. [입력 상태](../../src/components/risk-assessment-form.tsx), [본문과 revision 전달](../../src/components/task-forms.tsx), [변경 감지와 제출 기준](../../src/components/workspace-form.tsx)을 함께 확인한다. 깨끗한 화면 A → 화면 B 저장 → A의 부분 새로고침 → A의 일부 수정으로 실제 재현한 뒤, 입력과 기준 버전을 한 묶음으로 보존한다. 수정 전 실패와 수정 후 12개 브라우저 통과 결과는 진행 기록에 남겼다. 저장 결과 불명과 실제 DB 초기 조회는 아래 후속 범위다.
- **그다음 · 응답 유실 복구:** 서버 저장 후 응답만 사라지면 화면은 기존 revision으로 재시도해 충돌할 수 있다. 정적 감사에서 찾은 경로이며 아직 실제 응답 유실을 재현하지 않았다. 저장 요청별 식별자와 요청 내용 해시·저장된 버전/revision의 처리 결과를 같은 트랜잭션에 남겨, 같은 요청의 재시도는 처리 결과를 확인하는 설계를 우선 검토한다. 최신 본문이 같다는 사실만으로 자기 요청의 성공을 확정하지 않는다. 요청 처리 결과와 현재 버전을 권한 안에서 대조해 이미 저장됨/미저장/다른 수정 있음/확인 불가를 구분한다. 다른 수정이 있으면 현재 입력을 보존하고 저장본과 비교할 수 있어야 하며, 단순히 여러 입력칸을 모두 복사하라고 안내하는 데서 끝내지 않는다. 충돌을 피하려고 revision을 무조건 최신으로 바꾸지 않는다.

- 실제 모드의 업무·문서·본문 초기 조회가 하나의 DB 스냅샷인지도 별도 검증한다. 이번 클라이언트 RSC 재현·수정이 실제 Supabase 초기 조회 경합까지 해결했다는 뜻은 아니다.

## 토론과 선택지

| 접근 | 장점 | 반론·비용 | 결정 |
| --- | --- | --- | --- |
| 교육·선임 전용 화면부터 확장 | 다양한 업무의 입력 부담을 줄임 | 관찰마다 남은 일을 놓치는 공통 문제가 남는다. 과정·대상·시간의 승인 없는 자동 판단도 피해야 한다. | 현장 기록 다음에 교육 한 종류로 좁혀 진행 |
| 현장 기록 한 건의 후속 조치까지 연결 | 이전에 남긴 문제를 재방문·인계·재확인할 수 있음 | 단순 완료 버튼 추가로는 부족하다. 새 발견의 식별과 원본 연결부터 필요하다. | 저장 신뢰성 보강 다음 구현 |
| 모든 업무에 회차·일정·알림을 일괄 확대 | 재사용과 화면 통일에 유리 | 선임·교육·개별 발견의 의미가 다르며 날짜와 법정 주기를 잘못 묶을 위험이 있다. 불필요한 모델 확장이 크다. | 현재 범위에서 제외 |

- 디자인은 교육의 추상적 입력과 반복 방문 부담을 지적했다. 운영은 “새 서식보다 전날 남은 일이 오늘도 보이는가”가 먼저라고 반론했다. 결론은 현장 기록 흐름을 먼저 완성하고 교육은 한 종류부터 이어가는 것이다.
- 운영은 담당자·목표일만 추가하면 서로 다른 발견이 최신 문서에 섞인다고 지적했다. 디자인도 관찰별 식별·위치·실제 확인일과 짧은 첫 입력을 같은 범위에 넣는 데 동의했다.
- 개발은 현장 기록을 위험성평가 스키마로 그대로 처리하거나 모든 업무의 회차를 풀면 의미와 권한 경계가 흐려진다고 반론했다. 원본과 연결은 유지하되 실제 관찰·조치의 사실은 따로 저장한다.
- “자주 쓰므로 구매할 것”은 확인되지 않은 가설이다. 상품 가치는 이전 미해결 건을 놓치지 않는지, 인계받은 사람이 근거와 다음 행동을 찾는지로 검증한다.

## 다음 화면과 기록의 범위

1. **현장 기록 남기기:** 어디에서 무엇을 보았는지부터 묻는다. 사진은 나중에 연결할 수 있고 실제 확인일을 앱 접속일로 자동 확정하지 않는다. 위치·관찰·확인 사실·추정·모르는 내용을 구분한다.
2. **다음 확인 정하기:** 조치 필요 여부를 사용자가 확인하고 담당자와 직접 정한 목표일을 적는다. 미정·판단 전도 저장한다. 서비스 목표일과 법정 기한을 섞지 않는다.
3. **실제로 한 일 남기기:** 계획과 구분해 실제 조치 내용·수행일·관련 자료를 기록한다. 과거 계획만으로 수행 사실을 만들지 않는다.
4. **다시 살펴보기:** 누가 언제 무엇을 확인했는지, 문제가 남았는지를 남긴다. 미해결이면 다음 행동으로 돌아간다. 자료 저장·작성자 확인·검토와 조치·재확인 상태를 분리한다.
5. **오늘과 전체 지도:** 미조치·담당 미정·재확인 필요 중 저장된 근거가 있는 항목을 보여주고 해당 현장 기록으로 직접 이동한다. 기록 건수를 법적 이행률로 표시하지 않는다.

최소 구조는 기존 FORM_PHOTO 업무 아래 독립 현장 기록 여러 건을 두는 방식이다. 한 발견건에 한 문서를 연결하고 기존 문서 버전·증빙·검토 이력을 재사용한다. 각 현장 기록은 독립 ID와 수정 이력을 갖는다. 사용자는 “새 현장 기록”과 “이 기록 보완”을 구별한다. 기존 FORM_PHOTO 문서와 자유문장은 보존하고 참고 원문으로 연결한다. 기존 문장을 자동 분석해 담당자·기한·완료 상태를 만들어 이관하지 않는다. 위험성평가에 연결하더라도 관찰이 정식 평가나 법적 적합 판정으로 자동 바뀌지 않는다. 현장 기록의 개별 주소와 자료함에서의 역방향 연결을 제공하고, 홈 요약은 권한 적용 후 최신 버전을 일괄 조회한다. 고객 원문을 홈에 내려주거나 자료마다 조회를 반복하지 않는다.

이번에는 모든 교육·선임·도급 업무, 자동 법정 일정, 문자·메일 발송, 고객 원본의 브라우저 영구 저장, 전자서명·법적 승인 자동화를 추가하지 않는다. 실제 Storage·검사기는 연결 전 미검증 상태를 유지한다.

## 구현과 검증 순서

선행 P0는 본문과 저장 기준의 결합, 저장 결과 불명 시 복구다. 먼저 재현한 문제와 수정·검증한 문제를 구분해 기록한다. 이후 P1 현장 기록은 아래 순서, P2는 교육 한 종류로 진행한다.

1. 관찰 식별·수정·조치·재확인 구조와 기존 문서 연결을 설계한다. 서버·DB에서 조직/현장 권한, revision, 중복 제출 방지, 이력 보존을 검증한다. 범용 업무 엔진으로 확대하지 않는다.
2. 모바일 첫 기록과 같은 위치의 재개를 구현한다. 설명용 예시는 사실로 저장하지 않고 모르는 내용은 그대로 남긴다.
3. 조치 계획·실제 조치·재확인을 연결하고 자료 검토와 독립된 요약을 홈·지도에 반영한다.
4. 발견한 문제의 관련 사진·기록을 명시적으로 연결한다. 과거 수정 버전·검토·파일 검사 상태와 다른 고객의 권한 차단을 보존한다.
5. 다른 역할의 교차 검수와 관련 단위·DB·브라우저 검사를 실행한다. 아래 과제는 실제 기기·고객 참여 여부를 별도로 기록한다.

## 통과할 사용자 과제

- 가상의 계단 문제와 기계실 문제를 각각 저장한 뒤 장소·날짜·담당·증빙을 구분해 다시 찾는다. 하나를 보완해도 다른 기록은 바뀌지 않는다.
- 전날의 미조치 건이 오늘 새 기록을 추가하거나 자료 검토를 완료해도 남아 있다. 홈에서 바로 열어 다음 행동을 확인한다.
- 담당자·일정 미정과 아직 판단하지 못한 상태를 저장·재개한다. 빈칸을 해당 없음이나 완료로 바꾸지 않는다.
- 조치를 했다고 적어도 재확인 내용·확인자·날짜의 기록이 없으면 재확인 필요가 남는다. 남은 문제를 적으면 후속 행동이 유지된다.
- 기존 자유문장과 버전·증빙을 그대로 재열람한다. 새 구조를 만들 때 참석·수행·담당·완료가 자동 복사되지 않는다.
- 저장 실패 후 현재 화면의 입력을 유지하고 재시도해 같은 건이 중복 생성되지 않는다. 응답 유실로 저장 성공 여부를 모르는 상태는 확정 실패와 구분한다. 수정하지 않은 화면에서 외부 갱신을 받은 경우에도 오래된 본문에 최신 revision을 붙여 제출하지 않는다. 미저장 이탈을 안내한다. 모바일 OS가 앱을 종료한 뒤의 복구를 검증 없이 보장하지 않는다.
- 접근 권한이 없는 다른 고객/현장의 기록과 요약 건수는 보이지 않는다. 기존 권한 철회·민감자료·검토 제한이 유지된다.
- 360px에서 각 단계의 첫 질문·저장·남은 상태를 사용할 수 있고 키보드·모션 감소·확대가 작동한다. 실제 휴대전화의 가상 키보드와 현장 네트워크는 별도 시험한다.

실제 시설관리 초보 고객에게는 첫 행동까지의 스크롤·도움 요청, 새 기록과 수정의 혼동, 미해결 건 회수 성공 여부를 관찰한다. 목표 시간이나 전환율을 실제 측정 결과처럼 제시하지 않는다.

## 후속 순서와 외부 확인

현장 기록 흐름 다음은 교육 한 종류의 대상 확인 → 실제 실시 → 참석 확인 → 남은 사람/자료 확인이다. 법정 시간·주기·면제는 승인 규칙 없이 계산하지 않는다. 실제 Supabase 환경, 파일 검사·복구, 출시할 범위의 법령 승인과 실제 고객 검증은 [제품 조직의 통과 조건](../PRODUCT_TEAM.md)에 따라 별도로 진행한다.
