# 반복 운영과 자료 회수 구현 계획

사용자 요청: 여러 역할로 토의·검수·개선을 반복해 실사용 가능한 수준으로 만든다. 조직과 통과 기준은 [제품 개선 조직](../PRODUCT_TEAM.md)을 따른다.

## 구현 순서와 검증

1. 위험성평가 회차를 서버·DB·데모에 추가한다. `관리 시작`은 최신 회차를 재사용하고, 명시적 `새 평가 회차 시작`은 빈 새 기록을 만든다. 검증: 중복 생성, 오래된 revision, 다른 현장, 과거 문서·수행·검토 보존.
2. 홈·지도는 현재 회차를 안내하고 상세에서 이전/다음 회차를 찾는다. 이전 회차의 미해결 사항은 별도 확인 대상으로 남긴다. 검증: 첫 회차 v1/v2와 다음 회차 v1을 구분하고 지난 내용을 재열람한다.
3. 위험요인의 안정 ID를 안내 위치와 함께 저장한다. 검증: 두 번째 위험요인 복귀, 삭제된 항목 안내, 저장 실패와 사실 데이터 불변.
4. 실제 자료함·검토함에 서버 검색·현장/상태 필터·페이지 이동을 추가한다. 검증: 101건 이상, 오래된 문서의 새 요청, 권한 밖 자료와 건수 비노출.
5. 파일 업로드 호출 실패·완료 응답 유실을 복구한다. 실패·사용 제한·장기 대기는 원본을 보존하고 저장 본문만 새 수정 버전으로 준비한다. 검증: 응답 재시도 멱등성, 권한·revision·검토 상태 검사, 검사 결과 유지, 파일 자동 복사 방지.
6. 모바일 지도에서 선택한 분야 제목과 첫 행동으로 포커스·스크롤을 연결한다. 검증: 작은 화면의 키보드 동선·모션 감소, 넓은 화면 동작 유지.
7. 구현자와 다른 역할이 교차 검수하고 발견한 결함을 고친다. 단위·DB·브라우저·빌드 검증 결과를 [진행 기록](../PROGRESS.md)에 남긴다.

## 범위와 보존

- 사용자 선택으로 시설관리 사업장부터 검증 후 확대, 모바일 현장 사용 우선, 단계 안내 + 전체 지도를 확정했다. 회차·재개·자료 조회를 모바일에서 완료할 수 있는지 우선 검증한다.
- 회차 번호는 서비스 정리 단위다. 법정 주기나 이행 완료를 자동 판단하지 않는다.
- 기존 문서를 새 회차로 이동하거나 자동으로 완료 처리하지 않는다. 이전 위험은 읽고 새로 확인해야 하며 수행·검토 사실은 이월하지 않는다.
- 실제 Supabase 설정이 없는 현재는 실제 Auth/Storage/검사기/복구를 검증했다고 보고하지 않는다. 설치되지 않거나 실행되지 않은 외부 서비스를 임의로 연결 완료 처리하지 않는다.
- 이 회차에서 법령 조문·적용 기준·기한을 새로 만들거나 승인하지 않는다.
