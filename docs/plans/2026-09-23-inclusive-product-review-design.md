# 여러 고객 관점의 반복 검수와 입력 복구

사용자의 2026-09-23 요청에 따라 13개 관점으로 검토 → 반론 → 개선 → 독립 재검수를 반복한다. 사용자가 이미 승인한 지속 개선 범위 안에서 진행한다. 에이전트의 역할 검토는 실제 고객 인터뷰·고령자 사용 시험·전문가 법령 승인이 아니다.

## 이번 회차의 판단

전 산업·규모를 지원하는 목표는 유지하되, 시설관리 모바일 시범 사용부터 검증한다. 승인된 법령 적용 규칙 0개, 미연결 조문 73개, 실제 Supabase 미연결을 완료로 바꾸지 않는다. 법령 적용 원장, 설비별 수행건, 본사 결정과 현장 집행 연결, 시민재해 별도 확인, 일반 업무 반출은 남은 제품 과제다.

공통 입력 신뢰성을 먼저 개선한다. 위험요인 삭제가 입력을 즉시 잃게 하고, 서버에서 거절한 날짜가 다른 단계에 있으면 고객이 수정 위치를 찾기 어렵다. 외관 전체 재작성이나 새로운 규칙 추가보다 기존 기록을 안전하게 다루는 흐름을 우선한다.

## 구현 선택과 수용 기준

1. 내용이 있는 위험요인을 입력에서 제외하기 전에 대상과 범위를 알려준다. 기본 행동은 계속 작성이며, 취소 시 ID·모든 값·현재 위치가 그대로 남는다. 제외 확정은 미저장 변경이고 이전 저장본·실제 위험 해소 상태와 구분한다. 빈 항목은 간단히 취소할 수 있다.
2. 날짜 오류는 서버의 검증을 유지하면서 해당 단계·위험요인·필드 위치를 돌려준다. 화면은 그 입력을 펼쳐 포커스를 옮기고 바로 옆에 이유를 표시한다. 다른 초안은 보존하며 실패 시 다음 진행·저장 성공 안내·새 버전이 생기지 않는다.
3. 한 화면의 주 행동, 글자 위계, 줄바꿈·확대·가림·키보드 조작을 실제 브라우저에서 확인한다. 취향 의견과 측정 가능한 결함을 구분하고 확인되지 않은 문제를 수정 완료로 적지 않는다.

4. 자료함은 제목 검색을 먼저 두고 현장·상태를 검색 조건으로 펼친다. 활성 조건은 자동 펼침, 조건 요약·결과수·초기화를 유지한다. 360×800 첫 화면에 실제 결과 제목이 보이고 가리지 않는지 확인한다.

## 역할 간 반론

- 디자인: 확인창 남발은 현장 입력을 늦춘다. 운영: 내용 있는 위험요인 전체가 사라지는 동작에는 대상과 범위 확인이 필요하다. 결정: 빈 항목 취소는 유지하고 내용 있는 항목만 보호한다.
- 운영: 일반 업무 내보내기가 고객의 자료 회수에 중요하다. 개발·제품: 입력 손실·오류 복구가 저장 자료의 신뢰성을 먼저 좌우한다. 결정: 이번에 입력 복구를 완료하고 내보내기는 미완료 P1로 남긴다.
- 초보 사용자: 숨은 항목을 찾아다니지 않아야 한다. 법령 검토: 편의를 위해 날짜를 자동 보정하거나 검증을 없애면 안 된다. 결정: 서버가 알려준 위치로 이동하며 사실 입력은 고객에게 맡긴다.

## 검증과 종료 기준

서버 단위 검사에서 실패 시 쓰기 없음·안정 ID·계획일과 실제일 구분을 검사한다. 브라우저에서 두 위험요인 중 숨은 오류 → 정확한 필드 → 수정 → 저장 → 재열람과 제외 취소/확정 → 지난 버전 보존을 확인한다. 작은 화면·큰 글씨·키보드·움직임 감소도 검수한다. 수정 담당 외 관점이 재검수하고 남은 문제·실행 증거를 제품 검토 목록과 PROGRESS에 남긴다.

회차는 한정된 결함의 검증이 끝나면 기록하고 다음 우선순위로 연결한다. 외부 환경·실제 고객·전문가 없이는 통과할 수 없는 문턱을 가상 토론으로 통과시키지 않는다. 자동 상시 실행이나 실제 고객 초대는 설정하지 않는다.

접근성 기준: [W3C 고령 사용자와 웹 접근성](https://www.w3.org/WAI/older-users/), [텍스트 200% 확대](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html), [웹 인터페이스 검토 기준](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md). 자료 열람일 2026-09-23.

## 2차 검수에서 추가한 수정

저장 후 상세 피드백과 일반 성공 띠가 중복되어 모바일 입력 하단이 가려지는 장면을 재현했다. 상세 피드백이 있을 때만 일반 성공 띠를 숨겨 상태 안내를 유지한다. 브라우저 회귀 검사에서는 입력 가림 판정 전에 다음 질문 초점이 이동하지 않는 문제도 발견했다. 저장 성공 이벤트를 입력 잠금 해제 뒤 전달하도록 옮기고 정확한 savedBasis·revision 보호는 유지한다. 포커스와 실제 입력 상하단 클릭 대상 검사를 모두 유지한다.
