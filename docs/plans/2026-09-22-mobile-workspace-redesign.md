# 모바일 업무 화면 재구축

사용자 승인: 토스 모바일 앱을 강한 참고 기준으로 디자인·사용성·편리한 UI/UX를 재구축한다. 기존 벤토 홈을 유지하는 제약은 해제한다. 모바일 현장 사용, 시설관리 우선, 단계 안내와 전체 지도라는 기존 방향은 유지한다.

## 디자인과 내용

- 시각 방향: 흰 작업 면, 차분한 회색 구획, 큰 핵심 질문, 파란 주요 행동 하나. Pretendard를 유지하면서 굵기·간격·정보량을 재설계한다. 상자·그림·안내 문구의 반복을 제거한다.
- 홈: 지금 할 일 → 남은 일 → 전체 지도 진입 → 저장한 기록. 실제 서버 상태로만 구성한다. 큰 설명 그림과 여섯 분야의 반복 카드 대신 현재 위치를 짧게 표시한다.
- 입력: 현재 단계 → 핵심 질문과 실제 입력 → 필요할 때 여는 설명 → 저장하고 다음. 사업장 정보와 위험성평가에 같은 원칙을 적용한다. 상세 단계 목록과 부가 정보는 펼침으로 남긴다.
- 자료·지도·공통 메뉴도 같은 글자·색·여백을 사용한다. 실제 연결된 회원 공간에도 공통 탐색과 스타일을 적용한다.
- 상호작용: 선택 항목의 색/테두리 반응, 하단 도움말 열림, 저장 상태의 짧은 전환. 입력 컴포넌트를 재생성하는 애니메이션은 사용하지 않는다. 모션 감소·키보드·포커스 복귀를 유지한다.

## 구현 경계

- 앱 고유 이름과 기존 아이콘·자체 도움 그림을 사용한다. 토스의 공개 제품 원칙과 정보 구성 방식을 참고하며 외부 디자인 SDK를 추가하지 않는다.
- 도메인 규칙, 우선순위, 확인되지 않은 사실, 저장 본문/revision 결합, 권한, 자료 버전과 수행·검토·접수 구분은 바꾸지 않는다.
- 기존 현장 기록의 독립 ID·조치·재확인 개발, 응답 유실 복구, 실제 Supabase·파일 검사·법령 승인 등 미완료 작업은 이 화면 개편의 완료로 간주하지 않는다.
- 기본 안내를 줄여도 실제 이행 절차·증빙 예시·남은 확인은 도움말과 상세에서 찾을 수 있어야 한다. 중요 오류와 미확인은 접어 숨기지 않는다.

## 작업 및 검증

1. 홈·사업장 입력·위험성평가를 분리 구현하고 공통 스타일로 통합한다. 검증: 모바일 첫 화면에서 실제 다음 행동/입력이 보이는지 캡처·DOM 위치 확인.
2. 공통 셸·자료 목록·도움말을 정리한다. 검증: 360px·데스크톱·확대·모션 감소·접근성 검사.
3. 실제 입력 → 저장 → 단계 재개 → 보완·증빙으로 이어지는 기존 브라우저 검사를 실행한다. 동시 수정·저장 실패의 보호를 별도 회귀 확인한다.
4. lint·타입/빌드·필요 단위 시험을 통과한 뒤 로컬 미리보기를 갱신하고 PROGRESS에 실제 결과와 미검증 범위를 기록한다. 실제 휴대전화·현장 고객 시험과 브라우저 반응형 검사를 구분한다.
