# Jev Ultrafast 도입 검토

검토일: 2026-09-21. 사용자가 지정한 대상은 [browser-use/jev-ultrafast](https://github.com/browser-use/jev-ultrafast)다. 현재 공개 main의 문서·코드와 우리 앱을 대조한 제안이며, 도입 승인·구현·실행 성과가 아니다. 디자인·고객, 개발·보안, 운영 관점의 에이전트가 독립 검토하고 반론을 대조했다. 실제 고객 시험이나 외부 법률 검토는 하지 않았다.

## 1. 권고

Jev Ultrafast는 **격리된 가상 환경의 탐색 검수**부터 작게 비교한다. 고객 화면에는 먼저 기존 단계 안내와 독립 현장 기록·조치·재확인을 완성한다. 이후 긴 인계 메모의 확인 질문을 좁혀주는 실험은 브라우저 실행기 없이 Jev 모델만 사용하는 별도 후보로 둔다.

현재 제품 우선순위인 저장 결과 확인·복구 → 시설관리 현장 기록 한 건의 조치·재확인 → 교육 한 종류를 바꾸지 않는다. 자동화가 기록의 식별·보존·권한·실제 수행 구분을 대신할 수 없기 때문이다. [기존 다음 개선안](2026-09-21-field-observation-review.md), [제품 요구사항](../01_PRODUCT.md), [초보자 원칙](../BEGINNER_SERVICE_PRINCIPLES.md)을 따른다.

## 2. 무엇을 도입하는지 구분

| 대상 | 확인한 역할 | 우리 앱에서의 의미 |
| --- | --- | --- |
| Jev 모델 | 정해진 선택지·점수·참거짓 성격의 질문에 구조화된 결과를 반환한다. 자유문장 생성기는 아니다. | 허용된 질문 후보나 탐색 의도를 제안하는 별도 실험 가능. [공식 설명](https://docs.typesafe.ai/introduction) |
| jev-ultrafast | 관찰한 DOM에서 동작과 대상을 선택해 브라우저를 조작한다. 글자 입력에는 별도 LLM을 호출한다. | 자동 브라우저 작업 도구이며 디자인 시스템·모바일 SDK·법령 지식 엔진이 아니다. [README](https://github.com/browser-use/jev-ultrafast#readme) |
| 우리 앱의 안내·기록 | 권한과 저장된 사실·버전에 따라 다음 행동을 계산한다. | 이 기준과 법령 적용·확인·수행·검토 상태는 우리 서버가 계속 관리한다. |

패키지는 Python 3.12 이상과 Browser Harness를 사용하는 0.1.0이며 MIT로 표시돼 있다. Next.js 의존성에 추가하는 방식과 다르다. 오픈소스 실행 코드와 외부 모델 서비스 계약·비용은 별개다. [패키지 설정](https://github.com/browser-use/jev-ultrafast/blob/main/pyproject.toml)

## 3. 역할별 토론과 반론

| 관점 | 기대 | 반론과 조정 |
| --- | --- | --- |
| 초보 고객·디자인 | “기계실 건 이어줘”처럼 의도를 말하면 알맞은 곳으로 이동 | 자동으로 여러 화면을 넘기면 실제로 무엇을 확인했는지 놓칠 수 있다. 한 가지 제안과 근거를 먼저 보여주고 현재 지도 위치·직접 선택을 유지한다. |
| 개발·보안 | UI가 바뀌어도 목표 중심으로 탐색하는 검수 보조 | 우리 앱 내부 처리는 이미 구조화돼 있다. DOM을 다시 읽고 클릭하는 계층을 기본 경로로 추가할 이유가 약하다. 기존 서버 동작·권한·버전 검증을 보존한다. |
| 운영·법령 관리 | 공개 법령·서식의 변경 후보를 찾는 시간을 줄임 | 공식 API·원문 수집 경로가 있으면 먼저 사용한다. 에이전트는 UI 탐색이 필요한 예외 후보에 한정한다. 원문 전체·별표·예외·시행일 대조와 규칙 승인은 별도다. |
| 구매자 | 기록 정리와 인계 시간이 줄고 남은 문제를 찾기 쉬움 | 빠른 클릭 자체로는 구매 이유가 약하다. 사람의 검토·수정 시간을 포함해 실제 반복 업무가 줄어드는지 확인한다. |

디자인 검토의 추가 반론: 짧은 메모의 “앞으로 할 일 / 실제로 한 일 / 아직 모름”은 직접 선택하게 하면 충분할 수 있다. 모델을 거쳐도 사용자 확인이 한 번 필요하다면 비용·대기·오분류를 늘리는 셈이다. 따라서 모델은 긴 인계 메모나 의미가 섞인 기록에서 질문 수와 수정 부담을 줄이는지 비교해야 한다.

| 법적 적용·서명·접수·완료 자동화 | 의무 해당 여부, 실제 교육·점검 수행, 신고 접수 확정 | 이번 도입 범위에서 제외 | 승인된 규칙·확인 사실·사람 검토·기관 접수 근거 필요 |

미응답을 해당 없음으로 바꾸거나, 파일이 열렸다는 이유로 증빙이 충분하다고 판단하지 않는다. 승인 규칙 0개라는 현재 법령 준비 상태도 바뀌지 않는다.

## 5. 고객 기능의 작은 설계 후보

설명용 가상 사례: “기계실 누수 발견. 업체에 연락했고 내일 수리 예정.”

1. 고객이 입력한 원문을 보존한다. 연락했다는 진술과 수리 계획을 서로 다른 내용으로 다룬다.
2. 현재 기록에서 허용된 확인 질문만 후보로 만든다. 예: 실제 조치 확인, 담당자 확인, 목표일 확인, 판단 보류. 빈 필드 확인처럼 코드로 알 수 있는 내용에는 모델이 필요 없다.
3. 모델을 시험한다면 후보 질문 ID를 제안하게 한다. 질문 문장은 미리 검토한 템플릿을 사용하므로 별도 문장 생성 모델을 추가하지 않는다.
4. 화면에는 “수리는 예정된 일로 적혀 있어요. 실제로 마친 조치가 있나요?”처럼 한 질문을 제안하고 직접 선택·건너뛰기를 제공한다. 실제 질문 내용은 원문과 비교 가능한 경우에만 사용한다.
5. 사용자가 직접 확인한 내용만 기존 저장 경로로 반영한다. “내일”의 기준일·시간대, 담당자, 실제 수행일을 임의 확정하지 않는다. AI 후보 수락은 법적 이행 검증과 다르다.
6. 지도는 저장된 상태에 따라 해당 현장 기록과 남은 재확인을 표시한다. AI가 완료율이나 안전 점수를 만들지 않는다.

“계단 물기 처리”는 수행인지 계획인지 불분명하다. “닦지 못했다”와 “닦았다”를 구별해야 하며, 후자도 수행했다는 입력 진술이지 독립 검증된 사실은 아니다. 높은 confidence만으로 작성자 확인을 대신하지 않는다. 공식 문서에서 confidence는 선택 확률 분포에서 계산하는 지표이며 우리 한국어 업무의 실측 정확도와 같지 않다. [confidence 설명](https://docs.typesafe.ai/confidence)

가능한 구성은 **사용자 메모 → 서버의 권한·버전 확인 → 허용 질문 후보 → 선택적 모델 제안 → 사용자 확인 → 기존 저장 → 저장 결과 확인**이다. 모델이 느리거나 실패하면 직접 질문 방식으로 계속 진행한다. 사진 분석·OCR·음성 입력은 이 저장소가 제공하는 기능으로 간주하지 않는다.

## 6. 현재 코드와의 접점

| 현재 경로 | 도입 시 지킬 경계 |
| --- | --- |
| [task-actions.ts](../../src/domain/task-actions.ts), [journey.ts](../../src/domain/journey.ts) | 남은 조치·보완·기한 등 결정적인 다음 행동을 유지한다. 모델 제안이 이 항목들을 감추거나 우선순위를 임의 낮추지 않는다. |
| [tasks.ts](../../src/domain/tasks.ts) | 일반 사진 기록은 위치·관찰·직접 확인·후속 조치 문자열이다. 독립 발견 ID와 조치·재확인 구조를 먼저 갖추고, 기존 자유문장은 그대로 보존한다. |
| [task-actions.ts 서버](../../src/server/task-actions.ts), [workspace-form.tsx](../../src/components/workspace-form.tsx) | 권한과 본문에 결합된 revision을 유지한다. 모델 결과도 입력 ID·버전·원문 기준에 묶고 입력이 바뀌면 폐기한다. |
| [document-panel.tsx](../../src/components/document-panel.tsx) | 작성자 확인·검토 요청·실제 수행을 자동 클릭 후보로 노출하지 않는다. 모델 추천 수락과 실제 업무 상태 변경을 분리한다. |
| [config.ts](../../src/domain/config.ts) | 현재 실제 AI/OCR 연결은 차단돼 있다. 키를 추가하는 것만으로 켜지는 상태가 아니다. 별도 구현·평가 없이 기존 차단을 풀지 않는다. |
| [기존 브라우저 시험](../../tests/e2e/journey.spec.ts), [저장 회귀 시험](../../tests/e2e/save-revision-refresh.spec.ts) | 확정 회귀·권한·저장 검증을 유지하고, 에이전트가 발견한 재현 가능한 문제는 기존 시험으로 고정한다. |

미완료인 저장 응답 유실 복구를 브라우저 재클릭으로 해결하지 않는다. 업무 단위 요청 식별·처리 결과 조회가 마련돼야 이미 저장된 요청과 실패한 요청을 구별할 수 있다.

## 7. 소스에서 확인한 제약과 설계상 영향

- 기본 브라우저는 1120×780, mobile=false로 설정된다. 기존 Chrome 프로필의 탭을 사용하는 구조라 고객·운영자 계정이 있는 일상 프로필에 연결하면 안 된다. 별도 프로필·실행 환경을 마련하고 그 격리를 검증해야 한다. [browser.py](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/browser.py)
- DOM 관찰은 파일·비밀번호·hidden 입력을 제외하며 기본 date 입력의 역할 매핑이 없다. 우리 실제 수행일·목표일 입력에는 그대로 맞지 않는다. hidden revision을 보지 않는 화면 신선도 검사는 서버의 버전 충돌 검사를 대체하지 않는다. [snapshot.js](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/snapshot.js)
- 일반 지침은 준비된 검색/제출 버튼 클릭을 유도한다. “초안까지만”이라는 프롬프트만으로 제출을 차단하지 않는다. 금지 동작을 후보에서 제외하고 실행기에서 재검증하며, 우리 서버/API도 해당 실행 주체의 허용 명령만 받아야 한다. 기존 회원 권한은 내용 확인·수행 기록도 허용하므로 읽기 전용 자동화를 보장하지 않는다. 이 자동화 전용 제한 계층은 아직 없는 도입 조건이다. 외부 사이트에서는 입력 즉시 저장도 고려하며 통제를 검증할 수 없으면 실제 입력을 맡기지 않는다. [questions.py](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/questions.py)
- confidence는 현재 실행 루프에서 기록되지만 낮을 때 자동 중단하는 정책은 없다. DONE은 모델이 고른 종료 상태이며 저장·수행·접수 성공의 독립 증거가 아니다. [agent.py](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/agent.py)
- uploads·frames·새 탭·canvas 등은 MVP 범위 밖이다. 전체 법령 원문·첨부 수집, 사진 분석, 실제 모바일 사용성 검증을 맡길 근거가 없다. [README 제한](https://github.com/browser-use/jev-ultrafast#evidence-and-limits)

이상은 정적 코드 검토 결과다. 우리 앱에서 에이전트를 실행해 사고나 실패를 재현했다는 의미는 아니다.

## 8. 정보 전송과 운영 비용

모델 요청에는 URL·화면 텍스트·입력값·최근 동작이 포함된다. 글자 입력 시에는 별도 텍스트 공급자로 필드 맥락과 화면 일부도 전달된다. 현재 예제 설정은 OpenRouter의 텍스트 모델을 사용한다. 스크린샷을 기본 루프에서 쓰지 않아도 정보 전송은 발생한다. [model.py](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/model.py), [예제 설정](https://github.com/browser-use/jev-ultrafast/blob/main/.env.example)

우리 [MFA 화면](../../src/components/mfa-forms.tsx)과 [초대 결과 화면](../../src/components/workspace-form.tsx)은 등록 키·초대 코드를 readOnly 일반 입력으로 표시한다. 비밀번호 칸 제외만으로 이 정보가 보호되지 않는다. 해당 화면은 모델 관찰 이전에 접근 범위에서 제외하고, 전송 데이터는 허용한 필드만 구성해야 한다. 실제 비밀값을 읽거나 전송하지는 않았다.

TypeSafe의 공개 개인정보 정책은 Input을 학습·미세조정에 쓰지 않는다고 설명하고 미국 호스팅을 명시한다. 무보관 약속으로 해석하지 않는다. [개인정보 정책](https://typesafe.ai/legal/privacy-policy)

별도의 [MCA](https://typesafe.ai/legal/mca)와 [DPA](https://typesafe.ai/legal/data-processing)가 공개돼 있지만 우리 계정에 적용되는 개별 조건·보존/삭제·재위탁·국외 처리·민감자료 적합성은 미확인이다. DPA의 민감 데이터 항목 N/A를 건강·사고 자료 처리 승인으로 해석하지 않는다. 텍스트 모델 공급자도 별도로 확인해야 한다. 첫 실험은 합성 자료만 쓴다.

공개된 7.073초 검색 시연은 초기 브라우저 준비·이동과 사후 독립 검증을 측정에서 제외한다. 비교도 한 과제의 세 쌍 반복이므로 한국어 시설관리 업무의 속도·신뢰성 근거가 아니다. 보고된 텍스트 호출 비용 역시 전체 작업 비용이 아니다. [측정 문서](https://github.com/browser-use/jev-ultrafast/blob/main/docs/performance.md)

우리 비용은 모델 호출 + 텍스트 호출 + 브라우저 실행 + 재시도 + 사람의 검토·수정 + 사이트 변경 유지보수를 함께 측정한다. 실행 코드가 공개돼 있다는 이유로 무료 운영이나 자체 호스팅 모델이라고 설명하지 않는다.

## 9. 실행을 제안하는 작은 비교 실험

아래는 제안이며 아직 실행하지 않았다. 계정·허용 예산·격리된 시험 환경이 준비되기 전에는 유료 호출이나 고객 자료 연결을 하지 않는다.

1. **합성 탐색 검수:** 미리 만든 가상 기록에서 “지난 미해결 찾기”, “특정 보완 의견 열기”, “지도에서 관련 업무 찾기” 등 8개 과제를 각 5번 실행하는 작은 비교를 설계한다. 날짜·파일·실제 인증 입력은 첫 범위에서 제외한다. 40번 성공도 일반 신뢰성 증명은 아니다.
2. **독립 판정:** DONE 이후 별도 Playwright 검증으로 정확한 기록 ID·버전·화면 위치·남은 상태와 불필요한 확인/수행/검토 요청이 발생하지 않았는지를 검사한다. DOM 클릭 가능성과 업무 성공을 별도 집계한다.
3. **실패 포함:** 느린 갱신, 겹친 버튼, 모호한 제목, 예시 문구, 페이지 속 잘못된 지시, 미지원 입력, 다른 고객 경로, 네트워크 단절을 포함한다. 오류 원인을 숨기거나 ‘변경 없음’·‘완료’로 치환하면 탈락이다.
4. **비교:** 기존 Playwright의 회귀 실행 시간과 성공률을 경쟁 목표로 삼기보다 새 결함 발견 수·재현 가능성·사람의 확인 시간·전체 비용을 측정한다. 확정 회귀는 기존 시험이 담당한다.
5. **고객 질문 실험:** 현장 기록 모델 완성 뒤 긴 한국어 메모의 계획/수행 주장/불명확을 구분하는 제안을 직접 선택 방식과 비교한다. 부정문·오타·시설 용어·혼합 시간·미확인 날짜를 포함하고 문구 조정에 쓰지 않은 별도 평가 자료로 확인한다.

고객 기능의 통과 기준은 질문·수정 부담 감소, 미확인 사실 보존, 입력 변경 후 오래된 제안 폐기, 모델 장애 시 직접 입력 유지다. 임의의 confidence 기준 하나로 합격시키지 않는다. 금지 동작·타 고객 정보 노출·무근거 수행 확정·저장 결과 오보고가 발생하면 확대하지 않는다. 가독성·실제 모바일 키보드·현장 네트워크·사람의 이해는 실제 고객 시험으로 검증한다.

## 10. 이번 검토에서 완료한 것과 남은 것

- 완료: 공식 저장소·모델 문서·공개 데이터 조건 확인, 현재 코드 접점과 제약 대조, 세 관점의 반론 및 적용 우선순위 정리.
- 변경: 이 검토 문서와 PROGRESS 기록. 앱 코드·의존성·환경 설정·DB 변경 없음.
- 미실행: 설치, API 호출, 브라우저 에이전트 실행, 한국어 정확도·지연·비용 측정, 실제 고객 참여. 기존 앱 검사를 이번 JEV 검증 결과로 재사용하지 않는다.
- 다음: 기존 저장 신뢰성과 현장 기록 개선을 이어가며, JEV 도입을 진행할 경우 위 합성 탐색 실험부터 별도 수행한다. 고객용 전면 자동 조작은 현재 권고안에 포함하지 않는다.
