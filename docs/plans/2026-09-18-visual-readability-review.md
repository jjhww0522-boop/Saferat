# 가독성과 시각적 설명 방식 재검토

작성: 2026-09-18. 상태: **사용자 “계획대로 진행해봐” 승인 · 구현 및 로컬 검증 완료**. 아래 내용은 승인 전 토론 이력이며 [실행 계획](2026-09-18-visual-readability-implementation.md)에 따라 구현했다. 실제 결과와 미검증 범위는 [진행 기록](../PROGRESS.md)에 보존한다.

## 1. 확인한 문제

- `src/app/globals.css`는 본문에 Pretendard/Noto Sans KR/Malgun Gothic 이름을 지정하지만 실제 웹폰트 로더·파일이 없다. 기기에 설치된 글꼴에 따라 표시가 달라진다. `task-design.css`는 h1을 Noto Serif KR/Batang 명조 400으로 바꾸어 굵은 고딕 안내 제목과 질감·강조가 다르다.
- 본문 기본값 16px과 별개로 `journey.css`의 안내·설명에는 12~14px, 모바일 지도 분류 설명에는 11px, 최근 위치에는 10px가 사용된다. 크기·굵기·행간을 역할별로 다시 정해야 한다.
- 실제 1440px 홈 캡처에서 큰 안내 영역에 비해 상태·이유가 작다. 우측 궤도 도식은 선택한 업무·현재 단계와 연결되지 않고 모바일에서는 숨겨진다.
- 360px 지도 캡처는 2열 분류 뒤에 업무 상세가 길게 이어진다. 글씨를 키우기만 하면 길이가 더 늘어나므로 요약·선택·상세의 분리도 필요하다.
- 현재 애니메이션은 짧은 등장·진행 막대 변화다. 도움말도 문단 위주여서 관찰→확인→기록 같은 실제 행동을 시각적으로 설명하는 역할은 제한적이다.
- 자동 접근성 검사 통과는 실제 고객이 쉽게 이해했다는 증거가 아니다. 기존 검증을 실제 사용성 검증으로 확대 해석하지 않는다.

## 2. 관점별 토론

디자인·개발·운영 관점의 에이전트가 동일 저장소와 캡처를 읽고 반론을 교환했다. 초보 고객 관점은 사용 시나리오로 검토했으며 실제 부서 회의·고객 인터뷰는 아니다.

| 관점 | 제안 | 반론 및 반영 |
|---|---|---|
| 디자인 | 큰 한국어 질문, 선명한 강조, 실제 작업 그림, 일부 벤토 배치 | 모든 영역을 카드로 만들면 강조가 사라짐. 큰 행동 1개와 보조 요약 2개를 기본으로 제한 |
| 개발 | 실제 폰트 공급, 역할별 글자 크기, 모바일 단일 열, 짧은 전환 | PPT의 고정 비율을 그대로 사용하면 확대·긴 문장에서 깨짐. 일반 웹 흐름으로 구현하고 입력 컨테이너 유지 |
| 운영 | 현재 업무·위치·저장 상태·남은 확인·저장/이동 버튼을 쉽게 찾게 함 | 진행 그래픽이 실제 이행 완료로 읽힐 위험. 기록 준비·위험 판단·개선 확인·검토를 분리 |
| 초보 고객 시나리오 | 지금 해야 할 일과 왜 필요한지, 실제로 무엇을 보고 적을지 이해 | 첫 방문 설명을 매번 다시 보거나 그림을 기다리는 부담. 직접 넘김·건너뛰기·다시 보기와 정지 그림 제공 |

## 3. 비교한 세 방향

| 안 | 좋은 점 | 한계 |
|---|---|---|
| **벤토 홈 + 설명형 작업 화면 + 자료 목록 — 추천** | 전체 현황과 한 작업의 집중을 함께 제공. 화면 목적에 맞는 표현 | 공통 글꼴·상태·버튼 기준을 세 화면에 일관되게 적용해야 함 |
| 전면 벤토 | 분야·현황 비교가 쉬움 | 많은 입력·서류를 작은 상자에 넣으면 읽기와 작업 순서가 다시 어려워짐 |
| 전면 슬라이드형 | 첫 학습에서 한 가지씩 이해하기 좋음 | 반복 업무·검색·수정·자료 비교에 이동 횟수가 늘어남 |

기존 크림·코랄·명조는 이번 비교의 고정 제약으로 삼지 않는다. 사용자 요청에 따라 다른 시각 체계를 제안하되 기존 디자인 원본과 결정 이력은 보존한다.

## 4. 추천 화면 구성

### 홈

- 가장 큰 영역: 지금 할 일 한 가지, 이유 한 문장, 해당 업무의 구체적인 그림, 주요 버튼 하나.
- 보조 영역 1: 전체 업무에서 현재 위치. 적용 확인이 필요한 상태는 그대로 표시.
- 보조 영역 2: 실제 데이터에 있는 남은 확인·보완. 표시할 내용이 없으면 숫자·긴급성을 만들지 않음.
- 최근 자료는 하단 목록. 자료 접근이 반복 사용에서 중요하다는 근거가 생기면 네 번째 요약 영역으로 비교.
- PC는 비대칭 2열, 모바일은 주 행동→현재 위치→보완의 단일 열. 작은 카드마다 채움색 버튼·큰 숫자·배지를 반복하지 않는다.

### 작업

큰 질문 → 한두 문장의 설명 → 구체적인 정지 그림/선택형 3컷 도움 → 입력 → 저장과 다음 행동 순서다. 현재 업무·단계·저장 상태는 같은 위치에서 확인할 수 있게 한다.

예시 장면(설명용, 사용자 사업장의 사실이 아님):

1. **찾기:** 통로의 상자를 강조하는 그림과 “사람이 지나는 곳에 걸리거나 부딪힐 물건이 있나요?”
2. **확인하기:** 작업자와 확인하는 그림과 “이곳에서 일하는 사람에게 언제 불편하거나 위험했는지 물어보세요.”
3. **기록하기:** 위치·상황의 입력 연결과 “확인한 내용을 적어주세요. 아직 확인하지 못했다면 모름으로 남길 수 있어요.”

예시를 실제 입력으로 복사·저장하지 않는다. 저장 후에는 “이 기록을 저장했어요”와 저장 버전만 갱신한다. 현장이 안전해지는 그림, 전체 의무 완료 체크, 법적 준수율을 만들지 않는다. 초기 반복 작업에서는 그림을 접고 같은 입력에 빠르게 접근할 수 있게 한다.

### 전체 지도와 자료

지도는 분야별 요약과 선택한 업무의 현재 위치를 함께 보여주며 상세 업무는 선택한 범위에서 펼친다. 자료·버전·검토 이력은 비교하기 쉬운 행과 목록을 사용한다. 정밀한 기록을 모두 카드 격자에 배치하지 않는다.

## 5. 시각 기준 제안

아래 수치는 이 제품의 시안 출발점이며 WCAG가 정한 글자 크기 규정이 아니다. 실제 한국어 문장·확대·기기에서 조정한다.

| 역할 | PC | 모바일 |
|---|---|---|
| 페이지/주 행동 제목 | 32~36px | 28~30px |
| 현재 질문 | 26~28px | 24~26px |
| 설명 본문 | 18px | 17~18px |
| 입력·레이블·주요 버튼 | 16~18px | 16~18px |
| 저장·보완·미확인 등 중요한 상태 | 15~16px | 15~16px |
| 보조 메타정보 | 14px 이상 | 14px 이상 |

- 한국어 산세리프 한 계열을 실제로 공급한다. 첫 후보는 Pretendard이며 제목 600~700, 본문 400~500으로 비교한다. 굵기가 늘어도 글꼴을 여러 종류 섞지 않는다.
- 본문 행간 1.6~1.75, 긴 설명 폭 제한, 의미 단위 줄바꿈을 사용한다. 카드 높이에 맞추려고 글자를 줄이지 않는다.
- 시각안은 밝은 회백색 배경·흰 작업 면·짙은 네이비 글자·선명한 파란 주요 행동을 제안한다. 색상만으로 보완·완료를 표현하지 않는다. 실제 색상 값과 대비는 대표 시안에서 검증한 뒤 확정한다.
- 그림은 현장·사람·서류의 관계를 설명한다. 필수 문구를 그림 속 글자로만 제공하지 않고 모바일에서도 그림의 의미와 텍스트를 유지한다.
- 이동·연결·저장 결과에만 약 180~250ms의 전환을 시안 출발점으로 사용한다. 설명 컷은 사용자가 넘기며 자동 전환하지 않는다. 모션 감소 설정에서도 같은 정보를 정적인 표시로 전달한다.

## 6. 다음 검증 단위

대표 두 화면을 같은 데이터로 비교한다: **오늘 홈**, **위험성평가의 관찰·기록 장면**. 디자인 방향을 확인한 후 실제 동작하는 두 화면에 먼저 적용하고 전체로 확대하는 순서를 제안한다. PC 우선 여부에 대한 사용자 답변 전에는 PC에서 정리하고 모바일에서 현장 기록하는 사용을 함께 검토한다.

- 초보자 5명 중 4명이 30초 안에 다음 행동을 찾는지(제안 목표, 현재 결과 아님).
- 모든 참여자가 예시와 실제 기록, 저장과 수행 완료를 구분하는지.
- 모바일 360px·PC 1440px·200% 확대, 키보드·화면낭독·모션 감소, 폰트 로딩 실패에서도 내용과 동작을 사용할 수 있는지.
- 입력→도움 열기/닫기→이전/다음→저장 실패→재시도→재접속에서 입력·저장 상태·버전이 유지되는지.
- 기존 서버 요약·권한·업무 상태 계산을 보존한다. 장면 전환 때문에 폼 전체를 새로 만들거나 원문 자료를 홈으로 가져오지 않는다.

## 7. 참고한 공식 자료

- [Pretendard 공식 저장소](https://github.com/orioncactus/pretendard): 한국어 웹폰트·굵기·가변 글꼴 제공 방식 확인. 실제 크기·구성 제안은 이 프로젝트의 판단이다.
- [토스의 라이팅 원칙](https://toss.tech/article/21022): 필요한 정보를 쉽게 쓰고 다음 행동을 예상할 수 있게 하는 원칙 참고.
- [W3C Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html): 200% 확대에서 내용·기능 보존 기준 참고.
- [W3C Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html): 불필요한 동작 제어·모션 감소와 정적 대체 참고.
