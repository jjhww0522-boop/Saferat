# 답변과 저장 결과에 반응하는 안내

사용자의 기존 재구축 승인과 2026-09-23 정정(색이 아니라 사용성·친절함·적시 정보·작동성·애니메이션)을 적용한다. 모바일 현장 사용, 시설관리 우선, 단계 안내 + 전체 지도를 유지한다.

## 문제와 선택

디자인 검토에서 세 가지 단절을 확인했다. 도급 역할에 답해도 관련 입력이 접혀 있고, 설명·교육이 필요하다고 해도 도움 없이 다음 기록으로 넘어가며, 초안 저장 후 홈은 질문보다 준비 단계 숫자가 먼저 보인다. 에이전트 검토이며 실제 고객 조사 결과는 아니다.

전체 대화형 앱은 입력·증빙의 재열람과 정정을 복잡하게 한다. 자동 팝업을 늘리는 방식은 현장 입력을 방해한다. 따라서 **기존 입력 안에서 답변에 따른 질문과 도움을 보여주는 방식**을 선택한다. 질문 선택이 자동 저장이나 자동 이동으로 이어지지 않게 한다.

## 이번 구현

1. 사업장 정보: 도급 역할 답변 바로 아래에 역할별 설명과 다른 업체 인원 입력을 펼친다. 모름과 0명을 구분하고 역할을 바꿔도 값을 지우지 않는다. 확인 화면의 누락·미확인 항목은 해당 필드로 직접 이동한다.
2. 위험성평가: 작업·장소를 첫 질문으로 두고 구분·담당·일정은 펼쳐 입력한다. '설명·교육이 더 필요해요'에는 방법 안내와 공식 자료를 연결하고, 다음 이동의 의미를 '확인 필요로 저장하고 다음'으로 명시한다. 도움말 열람을 교육 실시로 저장하지 않는다.
3. 실제 저장 성공: 해당 질문의 입력을 보관했다는 피드백과 다음 질문을 연결한다. 실패에는 표시하거나 이동하지 않는다. 새 입력·수동 이동 시 지난 성공 안내를 치운다.
4. 홈: 저장 버전이 있는 현재 위험성평가 초안에 한해 보던 질문을 보여준다. 보던 위치와 저장된 내용의 구분을 유지한다. 개선·보완·기한 우선순위는 그대로 둔다.
5. 움직임: 선택에 따른 안내 등장, 질문 전환, 저장 성공 확인에만 짧은 모션을 사용한다. 입력값·포커스를 재마운트로 잃지 않는다. 움직임 감소 설정에서는 애니메이션을 제거한다.

## 수용 기준과 검증

- 역할별 질문 표시/해제, 입력값 보존, 모름 유지, 보완 버튼의 정확한 포커스 이동.
- 첫 질문에 집중할 수 있고 전체 직접 입력에서는 기존 필드가 모두 접근 가능하다.
- 도움 요청 → 설명 보기 → 닫기 → 원래 입력 유지. 설명만 봐서는 교육 실시·날짜·참석자가 채워지지 않는다.
- 저장 실패 시 다음 화면/성공 피드백 없음. 성공 후 다음 질문과 저장 의미가 일치하고 새로고침해 초안을 다시 찾을 수 있다.
- 모바일 360px 입력과 저장 버튼 가림 없음, 키보드 복귀·모션 감소·접근성 검사. 기존 저장/동시 수정/미확인 값 검증 유지.
- lint, 프로덕션 빌드, 단위 검사와 변경 흐름의 브라우저 검사를 실행하고 실제 결과를 PROGRESS에 남긴다.

## 참조와 범위

[토스의 인터랙션 설계 설명](https://toss.tech/article/interaction)은 움직임을 피드백·다음 행동·진행 상황 전달에 사용하는 이유를 설명한다. 이 원리를 우리 기록 업무에 적용한다. 브랜드 자산이나 화면 전체를 복제하는 작업은 아니다.

DB·법령 규칙·인증·고객 자료 처리 경로는 변경하지 않는다. 승인된 운영 법령 규칙 0개, 미연결 조문 73개, 실제 Supabase/현장 기기/고객 검증 등 기존 미완료는 그대로 남는다. 저장 응답 유실 복구는 별도 후속 작업이다.
