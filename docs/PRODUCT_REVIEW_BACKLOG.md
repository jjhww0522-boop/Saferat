## 토론과 2차 검수 기록

- 디자인의 ‘확인창을 줄여야 한다’와 운영의 ‘내용 있는 위험요인 전체가 사라지는 동작은 보호해야 한다’를 대조했다. 빈 항목 즉시 취소와 내용 있는 항목의 명시적 제외를 나눈다.
- 운영은 일반 업무 반출을 우선 제안했다. 제품·개발은 입력 손실/오류 복구를 먼저 처리하기로 결정하고 OPS-02를 미완료로 유지한다.
- 자료함 상세 검색을 접으면 조건 발견성이 떨어진다는 반론에 따라 활성 조건은 자동으로 펼치며 제목·결과수·조건 지우기는 계속 보이게 한다.
- 서버 구현자와 별도 담당자가 권한 선확인·날짜 allowlist·유일한 위험요인 ID·실패 시 쓰기 없음·기존 스키마를 읽기 검수했다. 이 범위에서 새 차단 결함은 발견하지 못했다.
- 다른 담당자가 UI를 다시 검수해 **관련 시작일을 수정해 저장에 성공해도 이전 오류가 남는 문제**를 발견했다. 저장 성공에 오류를 지우고 해당 회귀 시나리오를 추가했다. 자동 테스트 라벨 1개와 기존 취소 시험의 새 확인창 조작 누락도 수정했다.
- 1차 통합 브라우저 검사 5개 중 4개 통과, 저장 후 다음 질문 포커스 1개 실패를 확인했다. 성공 이벤트가 저장 잠금 해제 뒤 전달되도록 옮겼다. 가림은 별도 캡처에서 재현되어 상세 성공 안내가 있을 때 중복 일반 성공 띠를 숨겼다. 실패했던 검사의 포커스·가림 기준을 모두 유지해 재실행했고 통과했다.
- 실행 명령·실패·재실행·최종 통과 수는 [PROGRESS](PROGRESS.md)에 기록한다. ‘독립 검수에서 발견 없음’은 실운영·법적 완전성을 증명하지 않는다.

## 법령 조사 근거와 승인 경계

2026-09-23 공식 원문을 읽어 제품의 빠진 연결을 검토했다. 새 수치·기한·법적 적용 규칙을 승인하거나 배포하지 않았다.

- [산업안전보건법 제3조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0003&lsiSeq=283449&urlMode=lsScJoRltInfoR): 업종·유해위험·규모 등에 따른 적용 범위를 별도로 확인해야 한다.
- [중대재해처벌법 시행령 제4조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0004&lsiSeq=277417&urlMode=lsScJoRltInfoR): 방침·위험개선·예산·권한·의견·비상·도급 등 연결이 필요하다. 위험성평가 자료만으로 전체 관리체계를 대표할 수 없다.
- [중대재해처벌법 제3조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0003&lsiSeq=228817&urlMode=lsScJoRltInfoR), [제9조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1016999985): 산업재해 장의 적용 범위와 시민재해 책임대상을 구분한다.

법적 산정 단위·예외·실질 지배관계·시민재해 대상·교육/검사/보고/보존 개별 요건은 실제 책임 있는 전문 검토자의 원문·경계사례 승인 전까지 확정하지 않는다. 고객 원본을 공개 데모에 입력하는 시험이나 실제 고객 초대는 수행하지 않았다.
