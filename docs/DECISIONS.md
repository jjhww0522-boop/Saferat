- 기록 빈도만으로 상품성이 검증됐다고 판단하지 않는다. 이전 미해결 회수·근거 연결·인계 성공을 실제 시설관리 고객에게 확인한다.

## 2026-09-21 · 역할별 반복 검수와 반복 운영

- 사용자 선택 확정: 단계 안내 + 전체 지도, 모바일 현장 사용 우선, 시설관리 사업장부터 검증 후 확대. Supabase 개발 환경은 아직 없으므로 연결 준비와 로컬 검증을 현재 실행 범위로 한다. 기존의 선택 대기·PC 중심 가정보다 이 결정을 우선한다.

- [제품 개선 조직](PRODUCT_TEAM.md)을 구성하고 초보 사업주·작업자·개발/보안·운영/검토·구매자 관점의 에이전트 교차 검수를 수행한다. 실제 고객 인터뷰·법률 전문가 승인과 구분한다.
- 사용자 요청에 따라 반복 업무의 회차, 정확한 작업 재개, 과거 자료 회수를 우선한다. 회차는 서비스 정리 단위이며 법정 주기나 이행 완료를 자동 판단하지 않는다.
- 새 평가에 기존 수행 사실을 복사하지 않고 이전 회차를 참조한다. 과거 미해결·미확인·보완 항목은 다음 회차에서도 숨기지 않는다.
- 위험요인은 배열 인덱스 대신 안정 ID로 재개한다. 삭제된 항목은 선택 안내를 제공한다.
- 자료·검토 조회는 서버에서 권한 적용 후 검색·집계·페이지 처리를 수행한다. 실제 검토 요청일을 기준으로 대기를 정렬한다.
- 파일 실패 복구는 원본 삭제나 검사 우회가 아니라 저장 본문을 별도 수정 버전으로 보존하고 필요한 증빙을 다시 연결하는 방식으로 한다.
- Supabase 설정과 실행 중인 Docker 엔진이 없어 실제 연결·파일 검사·복구의 통과를 주장하지 않는다. 상품 준비를 임의 점수나 테스트 개수로 판정하지 않는다.

## 2026-09-18 · 승인한 가독성·시각 설명 개편

- 사용자가 기존 시각 체계 교체와 벤토/설명형 화면 계획을 승인했다. [구현 계획](plans/2026-09-18-visual-readability-implementation.md)에 따라 홈·위험성평가 대표 화면과 공통 가독성을 개선한다. 앞선 크림·코랄·명조 결정과의 차이는 사용자 최신 승인에 근거한다.
- Pretendard v1.3.9 가변 WOFF2를 원본 그대로 자체 제공한다. 시스템 설치 여부나 외부 CDN에 의존하지 않고 한글 사용자 입력도 지원하기 위해 전체 글꼴을 선택했다. OFL과 출처를 포함하고 폰트 로딩 실패 시 대체 글꼴로 동작한다. 원본 약 2MB의 첫 로딩 비용은 남으며 저속망 성능을 검증했다고 주장하지 않는다.
- 홈은 기존 서버 요약과 우선순위를 사용한다. 실제 남은 항목이 있을 때만 보조 확인 영역을 만들고 자료는 저장한 기록 목록으로 제공한다. 조회시각 없는 자료의 최신순을 추정하지 않는다.
- 그림은 설명용 React SVG이며 반복 재생·자동 다음·실제 사실 자동 입력을 하지 않는다. 단계별 그림과 3컷 팝업은 순수 표시 상태만 변경한다. 실제 폼의 데이터·revision·저장/실패 처리는 기존 컴포넌트에 남긴다.
- 새 애니메이션 라이브러리나 서버/DB 상태를 추가하지 않는다. 실제 저장본·위험 판단·현장 이행·검토·접수의 기존 구분을 유지한다.

## 2026-09-18 · 승인한 안내 UX 구현

- 사용자가 구체 설계에 “진행해봐”로 승인했다. 추가 승인 요청 없이 홈·지도·사업장 입력·위험성평가·자료 연결을 구현한다. 별도 writing-plans 스킬은 설치되어 있지 않아 저장소 형식의 [실행 계획](plans/2026-09-18-guided-safety-journey-implementation.md)을 기록했다.
- 크림·코랄을 유지하고 한 가지 중심 행동·관계도·짧은 질문 묶음으로 바꾼다. 기존 목록은 ‘모든 업무 직접 찾기’로, 위험성평가의 전체 입력은 명시적 직접 입력 선택으로 유지한다. 지도는 사업장 입력 미완성 상태에서도 열리지만 실제 업무 생성의 최소 사실 확인을 우회하지 않는다.
- 지도는 후보 목록 전체의 법적 완료율을 계산하지 않는다. 위험성평가 v1 기록 준비의 7개 기준, 미판단, 명시된 개선·재확인 필요를 각각 보여준다. 일반 업무는 저장 버전·내용 확인·검토 상태를 표시한다.
- DB 0009는 사용자별 안내 위치를 비공개 테이블에 저장하고 권한을 검사하는 RPC를 추가한다. 위치·안내 닫음은 입력 사실·문서 버전·수행 기록과 분리한다. 데모는 기존 세션 상태의 메모리 저장소를 사용한다. 입력 원문을 브라우저 영구 캐시에 저장하지 않는다.
- 기존 요약 RPC를 확장해 동일 조회의 최신 버전·기록 준비·업무 revision·담당자·준비 목표·검토 상태를 반환한다. 홈은 이 스냅샷으로 변할 수 있는 업무 메타데이터를 맞춘다. 원문을 반환하지 않고 요청당 요약 감사 1건과 민감자료·배정/MFA 권한을 유지한다.
- ‘저장하고 다음’은 기존 저장 액션의 성공 이벤트에서만 이동한다. 실패하면 입력과 위치를 유지하며 다른 폼 제출·이탈·동시수정 보호를 재사용한다. 현재 입력 기준과 저장된 진행 상태를 구분한다.
- 팝업은 브라우저 dialog의 모달·키보드·포커스 복귀를 사용하고 CSS 전환은 모션 감소에서 비활성화한다. 새 애니메이션·지도 라이브러리를 추가하지 않는다. 실제 초보 고객 참여 결과로 자동화 테스트를 대신 보고하지 않는다.

## 2026-09-18 · 능동 안내·전체 지도 개편 검토

- 사용자는 현 구성이 초보자에게 다음 행동을 충분히 알려주지 못한다고 지적했고, 앱의 능동 안내와 전체 흐름·진행 위치 시각화, 중요한 업무 우선 처리, 애니메이션·팝업을 요청했다. 이를 기존 목록 중심 화면의 표현 보완보다 넓은 변경으로 기록한다.
- 코드와 기존 디자인·개발·운영 관점 작업자의 읽기 전용 검토를 대조했다. 등록 업무가 없으면 첫 업무를 직접 찾아야 하고, 수행 안내가 접힘 안에 있으며, 전역 위치·재개 연결이 부족했다. 실제 고객 조사로 보고하지 않는다.
- 추천은 ‘단계 안내 + 전체 지도’이며 대화 중심·자유 탐색 중심 안과 비교했다. 구체 화면·저장 계약·검증 기준은 [설계 초안](plans/2026-09-18-guided-safety-journey-design.md)에 남겼다. 상세 설계 승인과 앱 구현은 아직 진행하지 않았다.
- 후보 수나 화면 방문을 완료율로 사용하지 않는다. 기록 준비·위험 판단·명시된 개선 필요·실제 수행·자료 검토·접수를 구분한다. 자료의 의미와 연결이 없는 일반 업무는 실제 수행 진행률을 만들지 않는다.
- 다음 우선순위는 홈·지도·사업장 입력·위험성평가·자료 연결을 함께 바꾸는 개편이다. 회차 관리와 분야별 전용 흐름은 후속으로 보존하고 실제 인증·저장·법령 규칙 검증도 미완료로 유지한다.

## 2026-09-17 · 다음 행동·정확한 기록

- 사용자 승인 계획의 첫 묶음은 홈 다음 행동, 사업장 미확인 정보 바로가기, 저장·재열람 개선이다. 법령 전체 지도·AI 확대에 앞서 입력 흐름을 연결한다. 상세 합의와 후속 순서는 [계획](plans/2026-09-17-next-actions-design.md)에 보존한다.
- 요약은 최신 저장본에서 서버가 계산한다. 실제 모드는 원문 대신 최소 projection을 반환하는 일괄 RPC를 사용하며 권한·요약 조회 감사 1건을 남긴다. 데모와 SQL은 공통 사례로 검증한다.
- 자료 검토 중·완료 상태가 미해결 개선조치를 숨기지 않는다. 높은 위험도만으로 긴급 상태를 만들지 않는다. 준비 목표는 법정 기한과 구분한다.
- 명시적 저장과 원문 영구 캐시 금지를 유지하고 저장 상태·이탈 보호를 추가한다. 긴급 안내는 새 창으로 열어 입력·이탈 확인이 안내를 지연시키지 않게 한다.
- 미저장·저장 중에는 다른 폼의 검토 요청 등 제출을 먼저 저장하도록 안내한다. revision은 실제 편집이 시작된 시점에 고정하여 다른 화면 갱신으로 동시수정 검사를 우회하지 않게 한다. 자체 저장 성공·원래 값 복원 뒤 다음 편집에서 새 기준을 사용한다.
- 질문 ID는 정의·버전·순번으로 구성하고 질문 구조·순서를 변경할 때 정의 버전을 올린다. 저장된 스냅샷은 그대로 유지한다. 기존 원문 없는 질문에는 현재 질문을 추정해 붙이지 않는다.
- 기존 데이터를 이전·삭제하지 않는다. DB 변경은 0008 함수 추가이며 실제 Supabase 적용은 별도 연결 검증이 필요하다.

## 2026-09-17 · 위험성평가 버전별 내보내기

- 남은 작업의 첫 단위로 저장된 평가 버전의 HTML·JSON 사본을 구현한다. HTML은 모든 위험요인·미입력 항목을 펼쳐 인쇄/PDF 저장할 수 있게 하고, JSON은 저장 원문과 구조화 기록·원문 SHA-256을 함께 제공한다. 새 PDF 라이브러리나 외부 서비스를 추가하지 않는다.
- 현재/과거 버전의 다운로드 경로에 버전 ID를 명시한다. 미저장 입력을 섞지 않고, 작성자 확인·검토 상태는 선택 버전의 현재 상태임을 표시한다. 수행 기록은 문서 공통 이력임을 명시하며 평가 회차에 임의 배정하지 않는다.
- 증빙 목록과 검사 상태는 포함하지만 파일 원본·비공개 저장 경로·운영자 내부 메모는 제외한다. 사용자가 파일을 열어 확인하고 증빙 원본과 함께 보관하도록 안내하며 실제 보관 위치는 직접 기록하게 한다.
- 서버 실행 모드로 데모/실제 경로를 결정한다. 실제 다운로드는 사용자 인증, 문서/민감자료 읽기 권한, 소속 버전 확인, 기존 감사 조회 RPC를 재사용한다. 응답은 private/no-store 첨부파일이며 사용자 입력을 HTML로 실행하지 않는다.
- 내려받기를 수행·승인·제출·접수·법정 보존 완료로 저장하지 않는다. SHA-256은 원문 대조용이며 전자서명/접수 증명이 아니다. 사본은 서비스 전체 복원 파일이 아니며 실제 장기 보존·복구·보존기간 기산 검토는 계속 미완료로 남긴다.
- 반복 회차와 대량 내보내기, 업종별 안내·교육 흐름은 후속 구현으로 유지한다. 최신 사용자 실행 지시와 AGENTS의 저위험 기본값 원칙으로 진행하며 기존 미커밋 내용을 커밋·초기화하지 않는다.

## 2026-09-15 · 초보 사업주 안내와 위험성평가 단계 기록
