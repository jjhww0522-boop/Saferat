# 05. 개발 순서·검증 사례·출시 기준

작성일: 2026-09-14. 아래는 작업 지시와 인수 기준이며 실행 결과가 아니다. 이 문서 생성 시 앱 코드를 만들거나 아래 테스트를 실행한 것은 아니다.

## 1. 단계 진행 원칙

2026-09-18 최신 요구에 따른 다음 우선순위는 안내형 UX 개편이다. [검토안](plans/2026-09-18-guided-safety-journey-design.md)의 추천 범위는 A. 공통 상태·오늘·전체 지도 → B. 사업장 입력·위험성평가의 단계별 안내 → C. 자료·증빙·보완 연결이다. 세 묶음을 함께 바꾸는 범위이며 사용자가 승인해 구현했다. 검증 결과와 남은 제약은 `PROGRESS.md`를 따른다. 그다음 위험성평가 반복 회차와 교육·선임·도급·점검/건강 전용 흐름으로 확장한다. 실제 법령 원장·규칙 승인과 인증·파일 검사·복구 검증은 병행한다.

2026-09-17 승인 범위의 다음 행동·미확인 정보 이동·저장 재열람 개선은 구현·로컬 검증을 완료했다. 해당 [계획](plans/2026-09-17-next-actions-design.md)과 실행 기록을 보존하며 새 UX 개편 완료로 간주하지 않는다. P2·P3의 실사용 차단 기준은 유지하고 `PROGRESS.md`에서 계획과 실행 결과를 구분한다.

새 UX 인수 기준은 첫 이용자의 첫 업무 발견, 전체 지도에서 위치 파악, 실제 입력→저장→중단→재개→증빙·보완, 홈/지도/상세의 상태 일치다. 저장 실패·동시 수정·접근 권한·과거 버전 보존과 모바일·키보드·모션 감소도 검증한다. 실제 초보 사용자 5명 중 4명의 독립적인 첫 저장·재개·보완 수행은 목표이며 아직 측정하지 않았다.

P0→P1→P2→P3→P4→P5 순서를 기본으로 한다. 각 단계 안에서는 준비된 화면·인터페이스·테스트를 계속 구현한다. 외부 키·전문 검토가 없는 부분은 명확한 차단 항목으로 기록하고 그 외 작업을 완료한다. 승인 없는 법령 데이터나 가짜 외부 응답으로 차단 항목을 숨기지 않는다.

기술 구현, 실제 외부 연동, 법령 검토, 운영 준비 상태는 따로 기록한다. 법령 데이터 준비가 늦어져도 UI·규칙 엔진·RLS·테스트 구현은 계속할 수 있다. 기술 구현이 끝났어도 법령 제공 범위가 미검증이면 실사용 판정 서비스로 공개하지 않는다.

## 2. P0 — 작업 환경과 구조

작업:

- 기존 저장소·지침·파일·실행 환경·git 상태 확인. 비밀값은 출력하지 않음.
- 새 프로젝트면 공식 문서에 맞는 지원 버전·패키지 관리자를 선택하고 이유·버전 고정.
- 화면/도메인/서버/연결부/데모/테스트 영역 구성.
- `docs/DECISIONS.md`, `docs/PROGRESS.md`, `.env.example`, 실행 README 생성.
- demo/live 설정과 잘못된 설정 처리, 시험용 자료 표시 구현.

완료 기준: 개발 서버를 시작할 수 있고 기본 화면을 열 수 있다. 실제로 확인한 환경·명령을 기록한다. API 키 없이 데모를 실행할 수 있지만 실사용 기능이라고 표시하지 않는다.

## 3. P1 — 연결된 사용자 흐름 데모

작업:

- 한국어 모바일 회원 화면, 운영자 화면, 공통 사고 화면.
- 단계별 사업장 입력과 OCR 후보 확인 화면, 직접 입력.
- 시험용 적용·비적용·확인 필요 규칙 엔진과 의무 상세.
- 자료 업로드 체험·초안 미리보기·활동 기록·검토·보완·재제출.
- 가상 고객·현장 데이터와 원본/새 버전 표현, 동일 저장소 공유.
- 긴급 안내와 공개 연락 화면. 미검토 사고별 세부 안내는 비활성/준비 중으로 정확하게 표시.

완료 기준: 가상 A고객의 입력→업무→제출→JH보완→재제출→검토 이력을 직접 실행할 수 있다. P1 권한 시뮬레이션은 P2의 실제 권한 검증을 대신하지 않는다. 실제 파일 업로드를 받는 공개 데모는 만들지 않는다.

P1 검증: AC-01~06, AC-12~16, AC-21의 데모 경로. 저장·권한 테스트 미구현 여부를 보고한다.

## 4. P2 — 실제 인증·저장·검토 기반

작업:

- 실제 계정·조직 소속·현장 권한·고객 초대 구조. 초대 발송은 실제 권한이 있을 때만.
- PostgreSQL 마이그레이션·RLS·최소 권한·비공개 파일 저장소.
- 원본 버전·검토 건·의견·보완·행위 이력 영속 저장.
- 운영자 배정·추가 인증·지원 범위·철회, 내부 메모와 민감자료 권한.
- 업로드 검사·격리·다운로드 권한·감사 기록·백업 기본 구조.
- 실제 고객 자료가 데모 경로로 들어가지 않게 차단.

완료 기준: 다른 고객/현장의 읽기·쓰기·파일·목록·내보내기 접근 거부가 실제 DB·서버 경로에서 확인된다. 마이그레이션과 파일 저장소를 복구할 수 있는 방법을 문서화한다. 설정이 없으면 연동 미검증으로 남기고 로컬 테스트 가능한 구조까지 완성한다.

P2 검증: AC-07~11, AC-17~20, AC-28~30. 실제 비공개 시범 운영에도 파일 검사와 권한 검증은 필요하다.

## 5. P3 — 법령 원장·승인 규칙·활동·사고 보고

작업:

- 법령 조사 범위·조문 처리·의무·출처·서식·규칙 버전 관리.
- 사실 스냅샷·시점·산정 정의·예외·3값 논리·설명 가능한 평가.
- 규칙 검토/배포 권한·승인 기준·영향 분석·철회·재평가.
- 반복 의무·기한·교육·선임·점검·개선 상태 연결.
- 관할·연락처 관리, 법령별 사고 보고·공식 서식 안내·제출 증거.
- 제공 범위와 미검토 범위를 회원 화면에 반영.

실제 규칙은 주된 법령의 정의·적용·예외·시행일을 함께 확인할 수 있는 범위부터 작성한다. 규칙 수를 채우기 위해 임의의 의무를 만들지 않는다. 검토 대기 규칙이 있어도 원장 UI와 시험용 엔진은 구현할 수 있다.

완료 기준: 승인된 규칙이 있는 범위에서는 결과 재현이 가능하고, 없는 범위는 명확히 확인 필요로 남는다. 실제 법령 규칙은 전문 검토 범위·기대 사례·배포 기록이 있어야 한다. 코드 구현 완료와 실제 규칙 공급 준비를 각각 보고한다.

P3 검증: AC-01~06의 실제 규칙 경로, AC-22~27, AC-31~34.

## 6. P4 — OCR·AI·문서 출력

작업:

- 등록증 OCR·필드 원문 위치·사용자 확인·수동 입력·실패 복구.
- 필요할 경우 국세청 대조를 별도 연결. 실제 소속 권한과 분리.
- 승인된 요구사항·권한 있는 문서로 AI 누락·불일치·확인 필요 제안.
- 검토된 자체/법정 템플릿 구분, 계획 초안·사진 점검대장·한글 PDF.
- 작업 큐·비용 한도·멱등성·재시도·문서/모델/프롬프트 버전.
- 공급자 데이터 처리조건과 외부 전송 경로 확인.

완료 기준: 실제 연결을 했으면 소수의 비개인 시험 자료로 요청·응답·오류·과금 기록을 확인한다. 연결하지 못했으면 mock 동작만 검증했다는 사실을 표시한다. AI 초안이 법적 승인·현장 이행·기관 접수로 바뀌지 않는다.

P4 검증: AC-12~20, AC-35~39.

## 7. P5 — 시범 운영·상품·출시 준비

작업:

- 무료/유료 기능 권한·사용 한도·운영자 처리량·계약별 사람 검토 배정.
- 정기 검토 결과, 지원시간·응답 기준, 미처리·장애 대응.
- 외부 법령 검토·보안 검토, 개인정보 처리·보존·위탁·국외 처리 확인.
- 데이터 내보내기·삭제/보존 보류·DB와 파일 백업 복구 시험.
- 실제 사용 지표와 비용·지원시간 측정. 광고·정부지원 수익은 0원 기본 가정.
- 사업자등록·재직 중 사업화·서비스 계약 등 운영 준비 확인.
- 공개할 업종·법령·기능 범위와 미검토 범위를 명시.

실제 결제·광고 SDK·기관 제출 자동화는 수요와 운영 조건을 확인한 별도 작업으로 둔다. 무료 베타 출시가 법령 검증·정보 보호를 생략할 이유가 되지 않는다.

완료 기준: 아래 출시 차단 항목이 해소되고, 제공 범위를 설명할 수 있으며, 제한된 시험 사용자로 실제 흐름·비용·지원 부담을 확인했다. 공개 배포 실행은 해당 사용자 요청 범위에서만 진행한다.

P5 검증: AC-40~42와 출시 차단 항목에 해당하는 실제 운영 설정. 앞선 단계의 테스트는 설정·코드 변경으로 영향을 받는 경우 또는 남은 위험을 확인할 때 재실행한다.

## 8. 핵심 인수 사례

‘실제 규칙’ 사례는 전문 검토로 정해진 기대 결과를 사용한다. 예시 숫자가 모두 법정 임계값이라는 뜻은 아니다. 표의 기대 결과를 충족했다고 기록하려면 해당 환경에서 실행한 근거가 있어야 한다.

| ID | 상황 | 기대 결과 |
|---|---|---|
| AC-01 | 실제 인원 0 / 미응답 / 4 / 5 / 20 / 50 / 500 / 501 | 숫자·미응답·산정 기간 보존. 구간 문자열로만 계산하지 않음 |
| AC-02 | 승인된 임계값 N의 N-1/N/N+1과 `<`, `<=` 등 | 전문 검토된 경계 기대값과 일치 |
| AC-03 | 같은 업종·인원, 다른 설비·계약·실제 작업 | 해당 사실에 의존하는 규칙만 근거에 따라 변화 |
| AC-04 | 인원 산정 기간 또는 역할 불명 | 해당 없음이 아닌 확인 필요·필요 질문 |
| AC-05 | 예외 조건 unknown, AND/OR/NOT 조합 | 명세의 3값 논리, 누락값의 false 강제 변환 없음 |
| AC-06 | 규칙/조사 범위가 비어 있거나 미검증 | 법적 의무 없음·준수 100% 표시 금지 |
| AC-07 | A계정이 B의 ID로 API 읽기·쓰기·삭제 | 자원·DB 권한 차단, 정보 유출 없음 |
| AC-08 | 같은 고객의 허가 안 된 현장 접근 | 조직 소속만으로 현장 권한을 얻지 못함 |
| AC-09 | 다른 고객 문서/현장 FK 조합 삽입·변경 | 서버와 DB에서 거부 |
| AC-10 | 운영자 배정 없음·만료·철회·추가 인증 없음 | 해당 원문·다운로드 접근 차단 |
| AC-11 | 권한 없는 검색·집계·내보내기·뷰·RPC | 우회 접근 및 내부 메모 노출 없음 |
| AC-12 | 복수 업태·종목, 개업일과 발급일이 다름 | 각각 원문 보존·명확한 필드 확인 |
| AC-13 | OCR 실패·불일치·낮은 신뢰도 | 직접 입력·확인 대기, 허위 확정/위조 단정 없음 |
| AC-14 | 사업자 대조 일치, 가입자 소속 미확인 | 기존 고객 접근권한 자동 부여 없음 |
| AC-15 | 사진 업로드·점검대장/교육일지 생성만 함 | 실제 점검·교육 이수 완료로 자동 전환하지 않음 |
| AC-16 | 계획 예산·담당자·측정값 미입력 | 결정 필요·빈칸. AI가 사실을 생성하지 않음 |
| AC-17 | 원본 v1 검토 후 v2 업로드 | 기존 검토는 v1에 유지, v2 재검토 표시 |
| AC-18 | 동시에 같은 문서 수정·중복 재제출 | 버전 충돌 감지, 중복 생성·원본 덮어쓰기 방지 |
| AC-19 | 초안 출력·전화 클릭·제출했다고 입력 | 각각 생성/클릭/사용자 기록, 기관 접수 확정 금지 |
| AC-20 | 내부 메모·건강자료가 일반 담당자 경로에 포함 | 서버 응답·PDF·AI·알림에서 차단 |
| AC-21 | 로그아웃·AI 지연·무료 한도 초과 | 공개 긴급 연락·검토된 공통 안내 유지 |
| AC-22 | 사고 장소가 본사와 다름, 이동 작업 | 위치·보고 업무 기준 재확인, 가까운 관서로 대체 금지 |
| AC-23 | 미확인·변경된 관서 연락처 | 검증 상태·공식 조회 안내, 가짜 번호 없음 |
| AC-24 | 사고 피해·진단·발생일 미확정 | 확인 과제 유지, 신고 불필요로 자동 종결하지 않음 |
| AC-25 | 하나의 보고 기록만 등록됨 | 다른 법령의 적용 보고·조사표 업무 별도 유지 |

## 9. 검증 방법과 요구사항 연결

| 영역 | 방법 | 관련 요구사항 |
|---|---|---|
| 적용·기간·상태 | 고정된 사실/규칙/시점 기반 단위 테스트 | REQ-01,03,06,09,11,15 |
| DB·파일·계정 | 실제 권한 컨텍스트의 통합 테스트 | REQ-02,04,08,10,12,14 |
| 회원→운영자→회원 | 브라우저 E2E, 모바일 크기·실패 흐름 확인 | REQ-01~10 |
| AI·OCR·출력 | 계약 테스트 + 연결된 경우 실제 비개인 샘플 | REQ-02,05,07 |
| 운영·비용·복구 | 사용량 경합·정기 검토·복구 시험 | REQ-10,12,13,14 |
| 법령 내용 | 공식 원문·전문 검토·기대 사례 승인 | REQ-03,06,09,11,15 |

화면 스냅샷만으로 동작을 검증하거나, 구현과 똑같이 작성한 테스트만으로 법률의 정확성을 증명하지 않는다. 명령 실행이 불가능하면 실패/미실행을 구분하고 사유를 기록한다.

## 10. 실사용 출시 차단 항목

- 고객/현장 경계를 넘는 자료 접근 또는 서비스 비밀키 노출.
- 운영자 배정·파일/검색·AI 권한 검증 누락.
- 미검증 법령을 확정 판정하거나 데모 규칙을 운영에 노출.
- 미응답·빈 조사 범위를 의무 없음/준수 완료로 표시.
- 문서 생성·사진·전화 클릭만으로 수행·접수 완료 처리.
- 사고 긴급 경로가 로그인·AI·구독·운영자 응답에 종속.
- 원본 버전·중요 변경·과거 판정 재현 수단 부재.
- 실사용 파일 검사·개인정보 처리 경로·필요한 보존·복구 준비 미완료.
- 유료 사람 검토를 제공할 운영 범위·인력·응답 기준이 정해지지 않음.

해당 기능을 비활성화하고 범위를 줄여 안전하게 시험할 수 있는 경우 그 제한을 명확히 한다. 기준을 통과한 것처럼 기록을 바꾸지 않는다.
