# Saferat — 사업장 안전관리

## 로컬 업무 데모 실행

P0·P1: 가상 사업장 정보 → 자료·수행 기록 → JH 검토 → 보완 → 새 버전 재제출을 연결한 한국어 웹앱입니다. 실제 법적 의무 판정 서비스가 아닙니다.

필요 환경: Node 24 LTS, npm 11. PowerShell에서는 `npm.cmd`를 사용합니다.

```powershell
npm.cmd ci
npm.cmd run dev
```

`http://127.0.0.1:3000`에서 ‘가상 사업장으로 체험하기’를 선택합니다. 키 없이 실행됩니다. 설정을 바꾸려면 `.env.example`을 참고해 비공개 `.env.local`을 만듭니다. 실제 인증·저장 연결은 아래 P2 안내를 따릅니다.

- 회원 홈에서 분야별 업무와 관련 후보를 살펴보고 ‘관리 시작’ → 확인 내용·자료 준비 목표일 기록 → 증빙·검토 요청으로 이어갑니다. 전체 후보도 별도로 열람할 수 있습니다.
- 각 업무의 ‘근거 법령·준비 이유’에서 조문·공식 원문·활동/기록 의무·적용 조건을 확인합니다. 조문 미확인 항목과 자체 서식을 구분하며, 원문 확인만으로 사업장 적용이 승인되지는 않습니다.
- 공개 체험은 회원 역할로 고정합니다. 역할 전환 메뉴는 없으며 실제 중앙관제는 별도 운영 계정으로 `/ops/login`에서 진입합니다.
- 실제 자료·개인정보 입력 금지. 제공된 가상 샘플만 첨부할 수 있습니다.
- 서버 메모리 저장: 새로고침 유지, 서버 재시작·새 체험 시작 시 초기화. 여러 프로세스/공개 배포용 저장소가 아닙니다.
- `/emergency`는 체험 세션·AI·로그인 없이 열립니다.

## P2 인증·저장 기반

- `/login` → `/workspace`: Supabase 계정, 조직·현장 접근, 자료 원본·새 버전, 검토·보완·수행 정정 이력을 연결하는 코드입니다.
- 조직·현장별 RLS, 배정된 검토자의 AAL2 추가 인증, 민감자료 별도 권한, 초대 생성·수락·철회와 감사 기록을 구현했습니다.
- 실제 파일은 비공개 격리 저장 후 검사 완료 건만 다운로드하도록 제한합니다. 파일 검사 공급자는 미연동입니다.
- 키가 없으면 회원 공간의 로그인 입력·실제 파일 접수는 비활성입니다. 기존 데모는 계속 실행할 수 있습니다.
- `npm.cmd run test:db`로 로컬 PostgreSQL 정책·버전 이력·DB 복원·재시작 검증을 실행합니다. 실제 Supabase Auth/Storage 통합 검증과 구분합니다.
- 실제 설정·검토자 배정·버킷 생성·파일 검사·복구 절차: [P2 연결 안내](docs/P2_SETUP.md).
- 업무 기록·문서 연결·운영자 등록·추가 인증과 시험 실행: [회원·중앙관제 안내](docs/PORTALS_TASKS.md). 기존 검토자 배정 외에 별도 운영자 등록이 필요합니다.

## 업종·인원별 검토 목록

체험 시작 후 회원 홈의 분야별 목록·전체 후보 열람에서 기록을 시작합니다. 출처·CSV를 자세히 보려면 **더보기 → 업종·인원별 검토 목록** (`/app/checklists`)을 엽니다. 중앙관제의 법령 준비는 별도 권한으로 접근합니다.

- 업종 18개 묶음, 분야 8개, 검토 후보 78개: 기본·관리체계 / 선임·조직 / 교육·훈련 / 작업·점검 / 보건·건강 / 도급·건설 / 시설·인허가 / 사고·기록.
- 업종·분야·검색어로 찾고, 실제 작업·설비 조건을 추가해 업종 밖의 관련 후보도 포함할 수 있습니다.
- 인원은 미확인·0명·1~4·5~9·10~19·20~49·50~99·100~299·300~499·500명 이상으로 탐색합니다. 검토 순서만 바뀌며 인원만으로 후보를 제외하지 않습니다.
- 항목을 열면 적용 확인 조건·질문·증빙·공식 출처·확인 범위를 봅니다. 전체 법적 의무 목록이나 승인된 판정 규칙은 아닙니다.
- **현재 목록 CSV**: 필터 결과·출처·검토 상태·검토자/검토일/의견 빈칸을 내려받습니다. 의견은 파일에 기록하며 앱에 저장되지 않습니다.
- 전체 파일: [검토 문서](docs/CHECKLIST_REVIEW.md), [검토용 CSV](docs/CHECKLIST_REVIEW.csv). 한글 CSV는 UTF-8 BOM으로 저장됩니다.

항목 원본은 `src/domain/review-catalog.ts`입니다. 원본 변경 후 `npm.cmd run catalog:export`로 문서와 다운로드를 갱신하고 `npm.cmd run catalog:check`로 일치 여부를 확인합니다. 검토 의견은 재생성 대상 파일을 직접 수정하지 말고 사본에 기록하세요.

검증 명령:

```powershell
npm.cmd run typecheck
npm.cmd run catalog:check
npm.cmd run lint
npm.cmd test
npm.cmd run test:db
npm.cmd run build
npm.cmd run test:e2e
```

E2E는 프로덕션 빌드와 설치된 Microsoft Edge를 사용합니다. 실행기가 기본 3015번 포트에 시험용 서버·분리된 회원/검토자 세션을 만들고 종료합니다. 다른 포트가 필요하면 `$env:PLAYWRIGHT_PORT='3017'`처럼 빈 포트를 지정합니다. 기존 사용자 서버는 종료하지 않습니다. 실행 결과·미검증 범위는 [진행 기록](docs/PROGRESS.md), 디자인 변경은 [디자인 기준](docs/DESIGN.md), 법령 준비는 [조사 원장](docs/LEGAL_PREPARATION.md), 협업 상태는 [오케스트레이션 기록](docs/ORCHESTRATION.md)을 확인하세요.

# 원본 개발 문서 묶음

작성일: 2026-09-14 · 버전: 1.0 · 문서 상태: 개발 실행 명세

이 묶음은 JH와 논의한 제품을 코딩 에이전트가 구현하도록 정리한 작업 지침이다. 앱 소스 코드, 전 법령의 검증된 규칙 DB, 사업화 허가 또는 출시 인증을 제공한 것은 아니다. 기능 구현과 법령 데이터 검증은 별도로 진행한다.

## 1. 가장 쉬운 시작 방법

1. 압축을 풀고 `orca-safety-app-kit` 폴더를 Orca의 작업 폴더로 연다. 새 프로젝트라면 이 폴더에서 앱을 만들면 된다.
2. [ORCA_START.md](ORCA_START.md)의 **첫 실행 프롬프트** 전체를 Codex 또는 사용하는 코딩 에이전트에게 전달한다.
3. 처음에는 API 키 없이 가상 사업장으로 핵심 흐름을 실행한다. 생성된 개발 서버 주소를 열어 직접 확인한다.
4. 이후 같은 파일의 **다음 단계 프롬프트**를 전달해 실제 인증·저장·권한부터 연결한다.
5. 작업이 중단되거나 대화가 바뀌면 **이어가기 프롬프트**를 사용한다.

Orca 버전과 에이전트 연결 방식은 확인되지 않았으므로 특정 버튼·메뉴명·전용 명령어는 전제하지 않는다. 코딩 에이전트가 이 폴더를 읽고 수정할 수 있으면 사용할 수 있는 일반 Markdown 지침이다.

기존 프로젝트에 적용할 경우 파일을 덮어쓰지 말고 먼저 별도 폴더에 보관한다. 기존 `AGENTS.md`가 있으면 두 문서를 읽고 충돌을 비교한 뒤 프로젝트 지침에 필요한 내용을 합친다. 기존 코드·설정·잠금 파일을 임의로 교체하지 않는다.

## 3. 이번 문서에서 정한 기본값

- 작업명: **사업장 안전관리**. 상표·서비스명 확정이 아니다.
- 전 산업·전 규모를 담을 데이터 구조를 만들고, 자동 법적 판단은 검증된 범위만 제공한다.
- 모바일 웹 우선. 회원용 서비스와 JH용 운영 화면을 같은 앱·DB에 연결한다.
- 신규 프로젝트 기술 구성안: Next.js + TypeScript + PostgreSQL/Supabase. 기존 저장소가 있으면 기존 구성을 우선한다.
- 초기 고객지원 담당자는 JH 한 명. 유료 상품에는 정기적인 사람 검토를 포함한다.
- 무료 회원 확보 우선. 광고·제휴·기업 구독은 후속 단계로 둔다.
- 월 50만 원, 최대 12개월은 임시 현금 예산 상한이다. 요금제 가격이나 개발 기간 보장이 아니다.

## 4. 실행 결과에서 반드시 구분할 것

| 표시 | 의미 |
|---|---|
| 데모 | 가상 자료와 시험용 규칙으로 동작을 보여줌 |
| 구현됨 | 코드가 존재하고 해당 기능을 실행할 수 있음 |
| 기술 검증됨 | 명시한 테스트를 실제로 통과함 |
| 법령 검토됨 | 정해진 범위의 근거·조건·예외·시행일을 담당자가 확인함 |
| 실제 연동됨 | 실제 인증·저장·OCR 등 외부 서비스로 동작을 확인함 |
| 출시 가능 | 기술·법령·운영의 출시 기준을 충족한 제공 범위가 정해짐 |

‘데모가 실행됨’을 ‘실제 고객이 모든 법적 의무를 관리할 수 있음’으로 보고하지 않는다. 반대로 외부 키가 없다는 이유로 화면·도메인 로직·마이그레이션·테스트까지 미루지 않는다.
